# Sandbox 审计检查清单

## P0 - 阻断级问题

### 业务逻辑流转

- [ ] 流程是否闭环？起点到终点是否有明确路径
- [ ] 分支是否完整？if/else、switch 是否覆盖所有情况
- [ ] 边界是否覆盖？空值、零值、最大值等边界条件
- [ ] 异常是否处理？错误是否有明确的处理逻辑

### 多场景矩阵完整性（规划阶段强制产物，见 01 §4.1）

- [ ] 场景矩阵是否存在？正常/异常/极限/空值/并发/权限/超时 7 类是否齐备（**轻量豁免: complexity <2 精简 3 类——见 01 §4.1 落盘模板，task-107 W4**）
- [ ] 边界清单是否覆盖？边界值、临界状态、依赖缺失、竞态条件
- [ ] 反向用例是否存在？至少 1 个"按错误理解需求"的用例
- [ ] 矩阵是否随规划载体落盘？（plans.json 对应 plan 文件）
- [ ] 计划是否逐场景给出预期行为？禁止只列场景不写预期

### 迭代计划逻辑

- [ ] 依赖关系是否正确？前置任务是否完成
- [ ] 执行顺序是否合理？是否有并行冲突风险
- [ ] 前置条件是否满足？环境、数据、权限等

## P1 - 确认级问题

### 状态机流转

- [ ] 是否存在死锁？循环依赖或等待
- [ ] 变量是否被覆盖？同名变量在不同作用域
- [ ] 状态转换是否完整？所有状态都有明确的转换规则

### 跨端契约一致性

- [ ] 入参是否对齐？字段名、类型、必填性
- [ ] 出参是否对齐？返回结构是否一致
- [ ] 错误码是否统一？各端错误处理是否兼容

## P2 - 改进级问题

### 命名一致性

- [ ] 变量命名是否规范？驼峰/下划线风格统一
- [ ] 方法命名是否语义化？动词+名词结构
- [ ] 表字段命名是否规范？是否与业务术语一致

### 代码可读性

- [ ] 注释是否完整？关键逻辑是否有说明
- [ ] 逻辑是否清晰？是否有过深的嵌套
- [ ] 是否有冗余代码？重复逻辑是否抽取
