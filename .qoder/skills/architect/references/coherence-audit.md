# 方案贯通审计执行细则 (Coherence Audit Logic)

> **定位**: architect 技能 §6 的配套细则。方案 = 一张图（节点=数据对象/流程节点, 边=流转/依赖）；贯通审计 = 输出前校验整张图**可落点、可走通**。
> **核心原则**: 审计对象是**整张图**（含非主路径），不是主链路；审计以**需求为参照系**，以**现状为落点池**。
> **⚠️ 输出格式取代声明 (2026-09-02)**: 本文件 §"审计表模板"的三节分表（A/B/C）已由 [scorecard.md](./scorecard.md) 的**单表**（域×审计项×状态×得分×证据）取代——贯通审计与评分卡同源合一，禁止分别输出两张表。本文件保留的价值 = **逐层对表方法、逐节点走查、系统边界清单、断链模式速查**（检查方法学），模板部分仅作内部推演草稿，不用于最终输出。

---

## 三边校验模型

```
需求 (参照系)  ←──A 覆盖审计──→  方案 (一张图)  ←──B/C 贯通审计──→  现状 (落点池)
```

- **A 覆盖审计**: 需求 ↔ 方案 —— 每条需求有设计落点；方案无需求外设计
- **B 数据贯通**: 方案 → 现状 —— 数据对象存在/一致/闭环
- **C 逻辑贯通**: 方案 → 现状 —— 流程连通/完备/自洽

任意一边失败 → 方案未过审计 → 禁止输出规划。

## 逐层对表方法

### B 数据贯通 — 逐层对表

对方案中**每一个数据对象**，沿链路逐层核验：

```
入口(展示/入参) → 传输(接口/DTO) → 处理(服务/逻辑) → 落点(存储/外部)
```

每层检查 3 件事：

1. **存在性**: 该层引用的字段/结构在当前代码/契约中真实存在（文件名:行号证据）
2. **一致性**: 相邻两层的同一数据，命名/类型/语义/格式/单位完全一致
3. **连续性**: 数据在链路中**每层都有去向**——没有任何一层"收下后没有下文"

**反向追溯（防幽灵字段）**: 对方案的**每个输出/展示字段**，必须能回答"谁生产了它"——从输出端逆推到生产它的代码位置。回答不出 = 断链。

### C 逻辑贯通 — 逐节点走查

对方案中**每一个流程节点**（步骤/状态/分支），逐个回答：

```
这个节点之后是什么？  (有后续, 且可达终点)
这个节点之前从哪来？  (可从起点到达)
这个节点失败/异常/取消时走向哪里？  (非主路径同样闭环)
这个流程会不会终止？  (有终止条件, 无死循环)
```

**happy-path 陷阱**: 主流程走通 ≠ 流程贯通。审计清单必须**逐分支单列**：异常分支、边界条件、取消/回退路径、失败重试路径——任一分支"没有写后续"即断链。

## ★ 系统边界重点清单（断裂最高发区）

数据穿过系统边界时，以下 4 项必须逐一有落点：

| 检查项 | 断链信号 |
|-------|---------|
| 字段映射 | 跨边界字段名/类型不一致，或映射表缺失 |
| 超时控制 | 外部调用无超时设计（等待永不返回） |
| 重试/幂等 | 失败重试会重复提交，或重试无上限 |
| 异步/回调 | 异步结果无人消费，回调无对应处理节点 |

---

## 常见断链模式速查

| 模式 | 特征 | 归属 |
|------|------|------|
| 幽灵字段 | 方案引用了现状中不存在的字段 | B 存在性 |
| 定义漂移 | 同一数据两端命名/类型不一致 | B 一致性 |
| 有读无写 | 消费了无人生产的数据 | B 闭环性（反向追溯） |
| 悬空步骤 | 流程走到某节点后无后续 | C 连通性 |
| 裸分支 | 异常/失败路径未定义后续 | C 完备性 |
| 规则冲突 | 两个分支条件重叠或规则矛盾 | C 自洽性 |
