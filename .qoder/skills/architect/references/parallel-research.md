# Architect Skill - Parallel Research Mode

> 本文件为 architect skill 的并发调研模式详细参考，避免主 skill Token 膨胀。

## 触发条件

- 用户显式声明 `/architect --parallel`
- 或主 Agent 判断任务复杂度需要并发调研

## 适用场景

| 场景 | 触发条件 | 并发 Agent 数量 |
|-----|---------|----------------|
| 跨端新功能 | 用户声明 `--parallel` | 2-3 (按业务场景分配) |
| 架构重构 | 用户声明 `--parallel` | 3-5 (按模块分配) |
| 单端小改动 | 不触发 | 0 (主线程处理) |

## 执行流程

```markdown
Step 1: 主 Agent 分析需求
├─ 判断调研维度（按业务场景，不按技术端）
├─ 决定 Agent 数量和职责
└─ 为每个 Agent 生成调研指令

Step 2: 启动并发调研
├─ 使用 Claude Code Agent Tool
├─ subagent_type: "Explore"
└─ 每个 Agent 独立执行，不互相通讯

Step 3: 汇总结果
├─ 主 Agent 收集所有调研报告
├─ 发现矛盾 → 向用户确认
└─ 综合分析 → 做出架构决策
```

## Agent 约束

🚨 **仅调研，不规划**
🚨 **关键发现向用户确认**
🚨 **遇到阻断返回主线程处理**
🚨 **现状扫描必须有入口点**（新增）

## 容错保底

| 异常情况 | 处理方式 |
|---------|---------|
| Agent 执行超时 | 主线程降级为单线程调研 |
| Agent 返回阻断 | 主线程决定终止/调整其他 Agent |
| Agent 发现矛盾 | 主线程向用户确认后决策 |
| Agent 信息缺失 | 主线程挂起询问用户（新增） |

## Agent 指令模板

```markdown
你是一个调研 Agent，负责探查 [业务场景/模块] 的现状。

**调研范围**:
- 相关实体类
- 状态机定义
- API 接口
- 数据流向

**溯源约束**:
- 从入口出发（Controller/前端组件）
- 逐层溯源至 Entity 或外部服务
- 禁止无入口地全量 Grep 扫描

**输出要求**:
1. 发现清单（实体/状态机/API）
2. 调用链路图
3. 关键发现点（必须有具体文件名和代码位置）

**遇到以下情况立即返回阻断**:
- 无法定位入口点
- 关键信息缺失不明确
- 发现架构冲突

⚠️ 仅调研，不规划，不提出方案建议。
```

## 汇总报告格式

```markdown
## 并发调研汇总报告

### Agent 1: [业务场景 A]
**调研结果**: [摘要]
**关键发现**:
- [具体发现 1] (文件: X.java, 行: 123)
- [具体发现 2] (文件: Y.vue, 行: 456)

### Agent 2: [业务场景 B]
**调研结果**: [摘要]
**关键发现**:
- [具体发现 1] (文件: Z.py, 行: 789)

### 矛盾点
- Agent 1 发现 X，Agent 2 发现 Y，存在冲突
- 建议: [向用户确认路径]

### 综合分析
[基于所有 Agent 发现的架构决策]

⚠️ 所有决策必须有证据支撑，引用具体 Agent 发现。
```
