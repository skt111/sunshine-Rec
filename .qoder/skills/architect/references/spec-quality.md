# SPEC-QUALITY：spec 契约方法论（什么是好的 spec）

> **定位**: architect §1.9 spec 生成器的**质量判据权威文档**——生成期自检 + 反例集 + 治理注入清单。消费方: architect §1.9（spec 生成）、sandbox（评分卡复核）、audit（基线核对）。
> **版本**: V1.0.0（2026-09-09，task-105 W2 定稿）
> **消歧注记**: 本文 spec = **需求 spec**（plan 详情「需求基线」yaml = spec 契约），区别于"制品 spec 化运动"治理义（task-104 标题用义）——两义同词，本文只用需求义。

---

## 一、第一性定性：spec 是"设计约束契约"，不是第二个 intent

> intent 回答 **"为什么做、做什么算对"**（起点契约，禁技术方案）；
> spec 回答 **"怎么做/复用谁/守什么约束"**（设计约束层：域/复用/风格/数据）。

- spec 不是独立文件——它是 plan 详情内的 **「需求基线」yaml 节**（spec 段），与评分卡（质量面）共同构成 plan 的规格层；
- 每层只加自己的信息：spec 写设计约束，**不回写意图**（意图变更走 intent 文档 → plan revised）；
- 若未来出现跨角色消费（外部团队只读 spec 不读 plan）才重议 spec 独立成文件。

## 二、与 INTENT-SPEC 的分界（消费时点/执行者/机器面均不同）

| 维度 | INTENT-SPEC（意图判据） | SPEC-QUALITY（spec 判据） |
|------|------------------------|--------------------------|
| 写作期 | 澄清/建档（02 协议 + Step 0.5） | spec 生成（architect §1.9） |
| 执行者 | 澄清对话执行 AI（模式外主 Agent 亦可） | architect（唯一生成者） |
| 机器面 | V-Intent（frontmatter/引用/状态） | V-A7（基线 yaml 完整性） |
| 定位 | 起点契约（为什么/做什么算对） | 设计约束契约（怎么做/复用/数据） |

两文档不合并——合并会稀释"起点契约"定位（task-105 备选 B 否决理由）。

## 三、好的 spec 五判据（QUALITY——编号 Q1-Q5，避开与流水线 S 编号撞号）

| 判据 | 定义 | 自检问句 | 可机器化 |
|------|------|---------|---------|
| **Q1 域对齐** | 域节命中且非空（四态裁决） | 域词查 domain-index 命中了吗？节为空/锚点失效挂起了吗？ | 部分（V-A6 锚点校验） |
| **Q2 复用有据** | 三态裁决与 asset-catalog 事实一致 | 声称 REUSE 的条目真实存在吗？NEW 有资产缺口登记吗？ | 部分（V-A4 确认记录） |
| **Q3 风格匹配** | style-profile 引用且不复制细则 | 风格声明指向档案了吗？细则留在端级规则了吗？ | 人工 |
| **Q4 表真实** | 表清单经 T1 确认、列级语义可溯 | 表经过核对闭环吗？DDL 注释有来源标注吗？ | 人工（DDL 闭环） |
| **Q5 机器可校验** | yaml 合法、无 REPLACE_ME、键齐全 | validate-plans V-A7 能零告警解析吗？ | ✅ V-A7（运行时） |

## 四、结构规范（需求基线 yaml 五键——V-A7 解析契约）

```yaml
需求基线:
  域引用: domain-index domain 域名（未建档 → 域缺口登记）
  复用决策: REUSE/PARTIAL/NEW + 条目 id（含命中理由/反例摘要；NEW 记资产缺口）
  风格声明: style-profile 引用（档案未生成填"未生成"）
  表清单: T1 确认后操作表列表（无涉及表填 N/A）
  确认记录: A1/A2 防伪（触发步骤+回显文本——V-A8）
```

- 每个键填实值（REPLACE_ME = 未完成 spec，V-A7 将告警）；
- 关键裁决（REUSE/PARTIAL/NEW）必须含命中理由与反例摘要——audit 按基线核对实现（V-A4）。

## 五、反例集（什么不是好的 spec）

1. **方案混入意图层**: 把表/API 设计写进 intent 文档（违 INTENT-SPEC B——意图泄漏实现）；
2. **复用拍脑袋**: 声称 REUSE 但 asset-catalog 无该条目/未输出 A1 确认卡（违 Q2）；
3. **域节空读邻节**: 命中域节为空却静默读邻节（违 Q1——S7 P1-11 强制挂起）；
4. **表清单臆造**: 未过 T1 确认直接写表名（违 Q4——字段级幻觉温床）；
5. **基线占位未填**: 带 REPLACE_ME 落盘（违 Q5——V-A7 告警面）。

## 六、与下游的衔接（每层只加自己的信息）

```
intent（起点契约：为什么/做什么算对）—— .qoder/intents/ + INTENT-SPEC
  → architect §1.9 spec 生成（本判据 Q1-Q5 + 治理注入五步）
  → plan 详情「需求基线」yaml（spec 契约）—— V-A7 机器校验
  → god 阶段 2 消费 / audit 基线核对（V-A4/A6/A8）+ 意图核对（实现 vs intent）
```

- Q5 是 V-A7 的**生成期前置自检**（运行时校验唯一实现在 validate-plans.js §6.4，本文不重复定义）；
- spec 变更（基线修订）→ 走 plan revised 流程（需求基线 yaml 更新 + 演进日志），不回写 intent。
