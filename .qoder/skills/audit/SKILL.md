## 触发时机

- `/god` 执行前（必须）——**预审计（对方案/伪代码），通过后不写 `done`**
- 代码修改完成后（推荐）——**最终审计（对实现代码），P0=0 且 P1=0 通过后由审计执行方将 plans.json status 更新为 `done`**
- 发现潜在问题需要审计时
- 用户显式调用 `/audit`

> done 写入者唯一化：仅最终审计（代码修改完成后）通过时写入；god 前预审计只出结论不更新状态（时序见 Step 3）。

## 审计深度分级（V2.8.0——对齐 god 验证分级 L0-L3）

> 宗旨：裁剪“与变更无关的面”，不裁剪“变更性质对应的高风险面”（实证：真 P1 发现均来自后者；全量一刀切是耗时结构性根因）。

| 等级 | 适用变更类型（任一命中） | 审计范围 |
|------|------------------------|---------|
| **A1 轻量** | 纯文档/注释/文案/单文件低风险（无业务逻辑） | 事实一致性 + 协作影响面 |
| **A2 标准** | 工具链内部（CLI/脚本/模板）/ 单端业务代码 / 配置 | 全 P0 维度 + 按「触发条件」命中的 P1 维度 |
| **A3 深度** | 跨端（≥2 子系统）/ 核心保护清单文件 / 外部对接 / 装配·配置拼接类 | **全维度（不再按触发裁剪）** + 场景矩阵逐行 + 外部规格追溯 |

- **判定纪律**: 不确定取更高一级（宁高勿低）；`--quick` ≡ A1；A3 仅命中时启用（不做缺省）；
- **等级与维度映射**: 见「审计重点」表「触发条件」列——主 Agent 按变更类型生成“本次应查维度清单”并随输入协议传入。

**Red Flags 反合理化表（V2.9.1——降级条款旁对照）**

| 借口 | 现实 |
|------|------|
| "构建过了不用场景验证" | 构建绿灯 ≠ 场景覆盖（L0 ≠ L2——01 §6.3）；核心逻辑/接口/流程变更必须叠加场景级验证 |
| "--quick 省时间" | --quick ≡ A1（纯文档/低风险）；业务代码/跨端不适用——不确定取更高一级（宁高勿低） |
| "P1 不阻断先放行" | P1 裁量归用户，不是执行方自裁；P0 处理不可授权 |

## 参数

| 参数 | 说明 | 示例 |
|-----|------|------|
| `{planId}` | 显式指定审计的 plan（会话隔离主键，替代全局游标） | `/audit task-89` |
| `--files=<路径>` | 指定审计文件（逗号分隔） | `/audit --files=gatekeeper.py,planner.py` |
| `--scope=<范围>` | 审计范围 | `/audit --scope=python-ai` |
| `--quick` | ≡ A1 轻量审计（文档/低风险——范围见「审计深度分级」） | `/audit --quick` |

## 行为约束

- 🚨 **禁止审计自己编写的代码**（必须 spawn 独立 Agent）
- 审计报告必须物理写盘（规范见下）
- P0 问题必须阻断执行
- 连带影响分析为强制检查项

## 报告写盘规范（god 验签按此定位）

- **路径**: `.qoder/skills/audit/reports/`
- **命名**: `audit-{planId}-{YYYYMMDD}-{topic}.md`（planId 必须携带——god 验签匹配键）
- **frontmatter**: 含 `plan_id` + `signatures.audit_agent`（独立蓝军 ID；降级执行填 self 并标注）
- **内容**: P0/P1/P2 分级 + 【问题】【证据(文件:行号)】【建议】+ 通过/不通过结论
- **机器可断言结构（task-106 W3 · 2026-09-10）**: 报告**尾部**（正文之后）必须附结构行：

```
REPORT-STATS: plan_id={planId} P0={n} P1={n} P2={n} VERDICT={pass|fail}
```

  - **VERDICT 自洽（强制）**: `P0=0 且 P1=0 → pass`，否则 fail（与 done 写入门槛对齐——audit 是 done 唯一写入者）；
  - **多轮规范**: 结构行**恒为最新一轮状态**——终审后**更新原行**（全文件至多一条）；
  - **消费方**: god 读 audit 报告结构行按 P0=0 且 P1=0 双条件判定；
  - **存量豁免**: 2026-09-10 前报告无结构行不追溯。

> 存量报告（2026-09-02 前，如 `{date}-{topic}-对抗性审计.md`）无 plan_id，不参与 god 精确匹配（历史豁免）。

## 核心原则

| 原则 | 说明 |
|-----|------|
| **独立审计** | Subagent 执行，禁止自我审计 |
| **物理写盘** | 报告先写入文件，再发送消息 |
| **连带影响** | 审计必须包含修改对其他模块的影响分析 |

> **审计逃逸回流（V2.8.0）**: 后续阶段（沙盘/联调/生产）发现的缺陷 → 复盘“本轮审计为何漏”（漏=维度未触发/触发条件过窄/检查项缺失）→ 补触发条件或检查项（登记迭代日志；先例: 长任务复盘 6 缺陷→V2.7.9 三维度）。

### 代码来源判定

| 来源 | 审计执行者 | 原因 |
|-----|-----------|------|
| 当前会话编写 | **独立 Agent**（必须） | 角色隔离 |
| 其他会话/人类编写 | 主 Agent（可） | 已有独立视角 |
| 无法判定 | **询问用户是否接受降级** | 宁可谨慎 |

> **核心价值**: 具体功能逻辑规则流转验证，而非公共校验

| 级别 | 维度 | 触发条件（V2.8.0） | 说明 |
|-----|------|--------------------|------|
| **P0** | 业务逻辑正确性 | 始终（A1+） | 需求实现、分支完整、边界覆盖 |
| **P0** | 功能规则流转 | 始终（A1+） | 调用关系、数据流转、状态变更 |
| **P0** | **连带影响分析** | 始终（A1+） | 修改后对其他模块的影响（新增） |
| **P0** | **数据对齐验证** | 跨端/协议相关变更 | 跨端状态同步、协议语义一致性（新增） |
| **P0** | **多场景/边界覆盖** | complexity≥2（有矩阵节→逐行核验；无→存量标注/新 plan 记 P1 回指 architect——与基线/意图回指同构） | 对照 01 §4.1 场景矩阵/边界清单/反向用例（plan 详情落盘节）逐行核验实现与验证记录；未覆盖且实现缺失 → P0、已实现无验证记录 → P1；存量（created ≤ 2026-09-10）标注『矩阵缺失（存量）』不判 P1（task-107 W4） |
| **P0** | **DDL 一致性核验** | plan 引用 explorations DDL | 若 plan 引用 explorations DDL：实现字段/类型/约束/注释与 DDL 一致，无字段级偏差（新增） |
| **P1** | **测试证据审计** | plan 声明测试/验证证据（有检查点记录） | 单测边界用例存在性、场景验证证据与实现匹配；**保真核对（task-109 W6）**: 触达本体（只测依赖库=绕过代理层缺陷）、真实结构（伪造结构掩盖字段路径缺陷）、豁免正当性（核心逻辑无理由豁免——对照检查点「测试豁免记录」）——假证据/豁免滥用判 P1；**验证证据链（2026-09-11）**: plan 详情「验证证据」节 ↔ 检查点「场景验证记录/测试豁免记录」一致且引用可达；审计报告对应行须引用证据位置（检查点文件/节）——链路缺失或不一致（存量 carve-out 同「多场景/边界覆盖」行）判 P1（01 §6.3 三段链） |
| **P1** | 跨层契约一致性 | 跨端变更 | 前后端接口匹配、VO/DTO 字段对应 |
| **P1** | **验证面匹配** | 装配/配置/依赖拼接类变更 | 交付声称的验证面 vs 变更面：装配/配置/依赖拼接类变更的验证证据低于 L2（01 §6.3 验证深度分级——无启动冒烟证据且非豁免）→ 判 P1（构建绿灯不得宣称可交付；2026-09-15 复盘吸收） |

## 执行流程

### Step 0: 确定审计范围

**优先级规则（A 阶段：planId 显式优先，禁读全局 handoff）**:

| 优先级 | 来源 | 触发条件 |
|-------|------|---------|
| **规则 1** | 显式 planId + args | 调用方传入 planId（/audit {planId}）或 args 含 `files`/`scope` |
| **规则 2** | 当前 plan 详情"跨端交接"章节 / 检查点 | 本 plan 的交接记录（**不再读全局 .handoff_state.md**——多会话并发下其内容属于其他会话） |
| **规则 3** | Git diff | `git diff --name-only`（限定在本 plan 声明的范围内） |
| **规则 4** | 终止并请求 | 以上规则均无效 |

**规则 4 触发时**:
```
⚠️ 审计范围未确定

请通过以下方式之一指定审计目标：
1. 传递 planId: /audit {planId}
2. 在 plan 详情"跨端交接"章节记录修改文件
3. 提交代码变更以生成 Git diff
```

> **执行归属（V2.8.0）**: 本步三块核对（基线/意图/外部规格）由**审计 Agent 执行一次**（Step 1 prompt 附 planId 与文件路径）；主 Agent 仅按上方优先级规则确定范围并准备输入（变更面清单 + 证据路径——输入协议见 Step 1）。

**基线核对（S5 流水线 · 2026-09-07，复杂度 ≥2 plan 必查）**:

```
1. 读取 plan 详情「需求基线」节（yaml）：域引用/复用决策/风格声明/表清单/确认记录
2. 核对项（逐项 FAIL/PASS）:
   [ ] 裁决有据: REUSE/PARTIAL/NEW 与实现事实一致（声称 REUSE 但实现自造 = P0）
   [ ] 确认记录齐全: 复用决策存在但确认记录为空（A1/A2 缺失）→ P0 阻断（V-A4: 人为跳过确认 = P0，不给 P1 放行）
   [ ] 防伪: 确认记录缺触发步骤/回显文本 → P0 缺口（V-A8）
   [ ] 实现与基线一致: 表清单操作的表 ⊆ 实现涉及表（多表/少表 → P1 核对）
3. 基线节缺失（复杂度 ≥2 plan 无基线）→ 记 P1 并回指 architect（流程缺口）
```

**意图核对（task-103 W1 · 2026-09-09，复杂度 ≥2 plan 必查）**:

```
1. 读取 plan 行 `intent` 字段 → `.qoder/intents/{intent}`（5 要素，重点：期望结果/排除项）
2. 核对项（逐项 FAIL/PASS）:
   [ ] 期望结果行为已实现: 每条可观察行为有实现落点（缺 → P1 做错事指认）
   [ ] 无意图外范围: 实现功能 ∈ 意图+基线范围（意图外功能 → P1 scope creep）
   [ ] 排除项未被实现: intent 排除项无实现痕迹（执行了 → P1）
   [ ] 引用缺失: 非豁免 plan（≥2/非 todo/新）无 intent 引用 → 记 P1 并回指 architect（补建档或豁免注记——处置闭环，与基线核对 V-A7 回指同构）
```

**外部规格追溯（条件触发 · 2026-09-15 复盘吸收）**:

```
触发条件: plan/检查点声明引用外部规格文档（需求文档/验收清单/接口清单——如长任务实验的需求包）
1. 逐条目追溯: 规格文档每个可交付条目（节/清单行） → 实现物（文件/行为） → 验证证据（测试/探活/截图）
2. 核对: 遗漏条目 → P1（整节遗漏等严重者 P0 由审计裁量）；条目与实现语义不符 → P1
3. 输出: 核对表（条目 × 实现物 × 证据 × PASS/FAIL）写入审计报告（不新建文件）
```

### Step 1: 启动审计 Agent

**Agent 配置（planId 显式传入，禁止子代理读全局游标）**:

```json
{
  "subagent_type": "Explore",
  "prompt": "见 prompts/audit-agent.md（必须附 planId 参数）",
  "name": "code-auditor"
}
```

**输入协议（V2.8.0——事实输入，非结论；审计员对证据抽查核验真实性）**:

1. planId + plan/intent/基线文件路径（必传）；
2. **变更面清单**（文件与行域——锚定审计范围；缺失时审计员按场景矩阵推断并标注 [推断模式]）；
3. **机械/验证证据路径**（test/对账/扫描输出、验证证据文件——审计员抽查核验：文件存在性、断言与输出对应；**证据不实 → 判 P1**——不重复执行命令）；
4. 审计等级（A1/A2/A3——按「审计深度分级」判定）+ 本次应查维度清单（按「触发条件」列生成）；
5. 抽样规则（大变更面 >10 文件）: 高风险面全查 + 其余每维度抽查 ≥3 文件（报告写明抽样范围）。

**关键约束**:
- Agent 类型必须为 `Explore`（只读，无修改能力）
- **必须传入 planId**（子代理按 planId 读对应 plan 详情，不从 activePlan 间接寻址）
- **读取切片**: 审计上下文只含本 plan 内容，禁止全量 plans.json 入上下文
- 不传入编码时的上下文、假设、决策过程
- 审计 Agent 从零读取代码，无记忆污染

### Step 2: 等待审计结果

**超时处理**:

```
首次超时（180秒/3分钟）:
  → 询问用户选择:
    [A] 降级执行（主 Agent 执行，标注[非独立审计]）
    [B] 继续等待（+180秒/+3分钟）

二次超时（+180秒/+3分钟）:
  → 询问用户选择:
    [A] 降级执行
    [B] 继续等待（+180秒/+3分钟）
    [C] 跳过审计（风险自担，需确认）
```

> **设置原因**: Subagent 执行探查任务可能需要较长时间，最短等待时间设为 3 分钟

**消息接收**:

```
📊 代码审计完成

报告路径: {report_path}
审计文件: {count} 个
统计: P0={n}, P1={n}, P2={n}
状态: ✅ 审计通过 / ❌ 审计未通过
```

### Step 3: 处理审计结果

**结果判定**:

| 条件 | 动作 |
|-----|------|
| P0 > 0（未达上限） | 🔴 阻断任务完成，返回 God Mode 修复（plan 状态保持 in-progress）；**修复轮次计数**（写 plan 详情「修复轮次记录」节，与 sandbox 统一计数——上限与处置见 x-rules.repairLoop；**预审计（god 前）P0>0 的修复同样计入**，触发方=audit-pre） |
| P0 > 0 且达上限（escalation，见 x-rules.repairLoop） | 🔴 输裁决清单（逐项: 修复/延后/推翻 + 理由 + 若错代价 = Ruling 三要素）→ **落盘（唯一权威 = plan 详情）**: 「修复轮次记录」节追加超限行（`R{n}: {日期} {触发方} 超限 {P0数} {处置}`——append-only）+ 裁决清单全文随行落底；检查点存在时账本追加 `blocked` 行（引用镜像）→ **置 `blocked`**（owners.to_blocked 授权；并在 plan 详情记录原因）→ 升级人工（**不自动收敛**；回转路径: recovery blockedResolve②——人工裁决，读取座标见其条款） |
| P0 = 0 且 P1 > 0 | 🟡 询问用户是否修复 P1 问题（**自治授权变体（V2.9.2）**: 用户显式授权（god「自治授权语」生效）下不即时询问——P1 全部落账为 Ruling（载体=检查点「执行账本」ruling 行——对齐写入时机矩阵（god SKILL 执行账本节——固定锚）；plan 详情「裁决记录」节为引用镜像，收口补同步）→ 终审时在报告「**待裁决清单（P1 事后裁决）**」节集中呈现（编号/问题/处置/状态）供用户事后裁决；**done 门槛不变**（P0=0 且 P1=0——消项路径=清单集中裁决后处置: 用户"接受"=落账 ruling 消项 / "修复"=修复后消项）；**防伪**: 无落账记录 = 视为未授权（同 god 口径——授权凭证=账本 ruling 行）；**P0 处理不可授权**——保底不动） |
| P0 = 0 且 P1 = 0 | 🟢 审计通过，**先校验审计凭证：沙盘报告/审计报告缺失（[无独立审计凭证]）时，写 `done` 前必须取得用户显式豁免并落盘豁免记录（豁免记录写入审计报告文件头或 plan 详情）**；凭证齐备后由审计执行方将 `plans.json` 中该 plan 的 `status` 更新为 `done` 并同步 `updated`（in-progress→done 的所有者 = 审计通过者）；**activePlan 联动: 若 activePlan 指向该 plan，须同步改指其他 active/in-progress plan（validate #1 强制——缺失致校验 FAIL）**，标记任务可完成 |

**输出格式**:


## 错误处理

### 降级执行约束

| 条件 | 是否允许降级 | 说明 |
|-----|------------|------|
| 代码来源 = 当前会话编写 | ❌ **禁止降级** | 违反独立审计原则 |
| 代码来源 = 其他会话/人类编写 | ✅ **允许降级** | 已有独立视角 |
| 无法确定代码来源 | ⚠️ **询问用户** | 用户决定是否接受 |

**降级执行标注**:
```
⚠️ [非独立审计] 本审计由主 Agent 降级执行
原因: {降级原因}
代码来源: {来源}
```

### 常见错误场景

| 错误场景 | 处理方式 |
|---------|---------|
| Agent 启动失败 | 检查降级约束，询问用户是否降级 |
| Agent 超时 | 询问用户：降级/等待/跳过 |
| 报告写入失败 | 终端输出审计结果（Fallback）；**禁止无条件写 done——需用户显式豁免并落盘豁免记录（与 god [无独立审计凭证] 门禁闭环）** |
| plan 文件缺失 | 基于代码推断预期行为，标注 [推断模式]（预期行为来源: plans.json 定位 plan 文件；缺失时降级） |
| 审计范围未确定 | 终止审计，请求用户指定 |

**SendMessage 失败 Fallback**:

```
IF SendMessage 成功:
    → 完成
ELSE:
    → 终端输出: "📊 代码审计完成 | 报告路径: {path} | P0: {n} | P1: {n} | P2: {n}"
```

## 复查轻量模式（V2.8.0）

修订闭环复查（首轮 P0/P1 修订后复验）: 范围=**修订点 + 原问题清单逐项闭环**——不重跑全量维度；发现新面问题时按 A3 升级。报告结构行按多轮规范更新原行。修订前 append-only 核验:「修复轮次记录」节完整性（缺失/被改写→单链处置: 依账本镜像补录+人工确认，无法补录/确认→按已达上限口径处置——x-rules.repairLoop）。
