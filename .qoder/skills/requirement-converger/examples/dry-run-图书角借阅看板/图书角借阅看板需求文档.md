## 一、项目背景与目标

### 1.1 系统定位

图书角借阅登记的内部小工具：HR 管理员通过一个网页完成借出/归还登记，实时查看在借清单与逾期名单；借还动作自动向员工发送 OA 提醒消息。现状痛点：Excel 手工记账导致借还对不上、逾期无人知。

```
[H R 管理员] ──浏览器──▶ [借阅看板（本应用: 前端+后端）]
                              │                │
                        [HR 库 employee 只读]   [OA 消息推送（外部）]
                        [本应用库 book_loan 读写]
```

### 1.2 用户角色

| 角色 | 可做什么 | 不可做什么 |
|------|---------|-----------|
| HR 管理员（唯一角色） | 借出登记、归还登记、查看在借/逾期清单 | 修改 HR 库数据、删除历史借阅记录 |

### 1.3 建设范围（1 个页面）

| # | 业务域 | 页面名称 | 路由 | 说明 |
|---|--------|---------|------|------|
| 1 | 借阅台账 | 借阅看板 | `/library/board` | 借出/归还登记 + 在借清单 + 逾期高亮 |

### 1.4 交付物要求

| 交付物 | 要求 |
|--------|------|
| 前端工程 | 可构建（`npm run build` 零错误） |
| 后端服务 | 借阅登记/清单查询/OA 通知编排能力（含幂等与失败处置行为） |
| 数据库 | 新建 book_loan 表（DDL 授权范围内）；employee 只读对接（**严禁改动**） |
| 文档 | 接口契约回写、部署说明 |

## 二、总体要求

### 2.1 技术栈（强制）

| 层 | 技术 | 版本要求 | 用途 |
|----|------|---------|------|
| 前端框架 | Vue 3（`<script setup>`） | ^3.5 | 全部页面 |
| UI 组件库 | Element Plus | ^2.13 | 全部交互组件 |
| 构建 | Vite | ^8 | dev / build |
| 后端框架 | Spring Boot + MyBatis-Plus | 2.7.x | API 与数据访问 |
| 数据源 | HR 库（只读）+ 本应用库（读写） | 现存/新建 | 见 §五 |
| OA 推送 | 外部系统（不开发） | — | 按附录B 对接 |

### 2.2 部署形态（强制）

1. 独立部署，网关路径 `/library/`；前端路由 base `/library/`；
2. 开发端口：dev `8310`（`npm run dev`）；生产端口见 §十（留白 L4）；
3. 接口寻址：前端不含 baseURL（同源相对路径）；dev 态 Vite 代理 `/api` → 后端。

### 2.3 架构红线（强制）

1. 页面组件**禁止**直调 `axios`/`fetch`——所有 HTTP 请求经 API 封装层；
2. 前后端交互字段一律 `snake_case`；
3. 统一请求层完成响应拆包（见 §三.3）——调用方禁止双重解包。

### 2.4 构建命令与质量门禁

| 命令 | 说明 |
|------|------|
| `npm install` / `npm run dev` | 安装 / 本地开发（:8310） |
| `npm run build` | 生产构建（零错误为门禁底线） |

**质量门禁**：构建报错修复 2 次仍失败 → 挂起求助，严禁带病交付。

## 三、全局机制需求

### 3.1 认证与访问（强制）

- 复用现有免登接入方式（宿主携带 token 进入）——token 提取后无痕净化；请求层统一注入 `Authorization: Bearer {token}`；
- 401 → 清 token + 提示 + 跳转登录失效页。

### 3.2 权限模型（强制）

- 单一角色（HR 管理员）——无需模块级权限体系；后端仅校验登录态与 token 有效性。

### 3.3 统一响应约定（强制）

- 业务响应壳：`{code, message, data}`；`code===200` 视为成功并拆包返回 `data`；业务错误 HTTP 状态恒为 200，由 message 承载原因；
- HTTP 错误映射：401 → 登录失效处置；403 → "无权访问"；其他 → 网络异常兜底提示；
- 分页结构：`{ total, current_page, list }`（全项目唯一分页口径）。

### 3.4 枚举与常量（强制）

- 借阅状态 status ∈ {`BORROWED`, `RETURNED`}（无其他取值）；
- **逾期判定** = `status=BORROWED` 且 `due_date < 今天`（服务端计算并返回 `overdue` 布尔与 `overdue_days` 天数——前端不重复实现判定逻辑）。

### 3.5 消息与交互规范（强制）

- 登记成功 `ElMessage.success`；重复借出等业务错误展示后端 message；
- 归还操作需二次确认；提交按钮请求期间禁用 + loading（防重复提交）；
- 清单空态展示 `el-empty`；加载用 `v-loading`。

## 四、功能需求

### 4.1 借阅台账域

#### 4.1.1 借阅看板（`/library/board`）

**定位**：系统唯一页面——借出/归还登记与在借清单管理。

**布局结构**：顶部操作区（借出登记按钮 + 状态筛选）→ 在借清单表格 → 分页条；借出登记以弹窗表单实现。

**功能区规格**：

| 控件/列 | 数据源/行为 |
|---------|------------|
| 状态筛选（radio） | 全部 \| 在借 \| 逾期（默认"在借"） |
| 借出登记按钮 | 打开登记弹窗（图书编号、书名、借阅人 oprid、应还日期） |
| 表格列：图书编号/书名 | 直出 |
| 表格列：借阅人 | 展示姓名 + oprid（服务端联查 employee） |
| 表格列：借出日期 / 应还日期 | 日期格式统一 `YYYY-MM-DD` |
| 表格列：状态 | 在借/已归还 tag；逾期行红色高亮 + "逾期 N 天" |
| 操作列 | 在借行显示「归还」按钮；已归还行无操作 |

**前端状态机**：`idle → loading → ready`（查询）；`submitting`（登记/归还提交中，按钮禁用）；无轮询、无后台任务。

**关键交互流程**：

1. **借出登记**：点击登记 → 填写表单（图书编号/书名/借阅人 oprid/应还日期，默认借出日+14 天）→ 提交 → 后端校验（员工存在/该书未归还）→ 成功后关闭并刷新清单；
2. **归还**：在借行点击「归还」→ 二次确认 → 提交 → 成功后刷新（状态变为已归还，从在借视图移除）；
3. **逾期查看**：筛选"逾期" → 查看逾期名单（红色高亮 + 天数）。

**业务规则**：

- 同一 book_id 且未归还时**禁止重复借出**（后端拦截，前端展示 message）；
- 归还对已归还记录**幂等**（重复提交返回成功，不报错）；
- 应还日期不得早于借出日期（前后端双重校验）；
- 借阅人 oprid 必须存在于 employee 表（后端校验，不存在则拒绝）。

**数据依赖**：借阅登记、清单分页查询、归还接口、employee 信息联查、OA 通知（附录B §2.1）。

## 五、数据模型需求

### 5.1 数据源划分

| 数据源 | 内容 | 读写边界 |
|--------|------|---------|
| HR 库 | employee（员工信息） | 🚨 **只读**（禁写入/DDL） |
| 本应用库 | book_loan（借阅记录） | 读写（本次唯一 DDL 授权：新建 book_loan） |

### 5.2 表清单（2 张）

| 表 | 用途 | 关键约束 |
|----|------|---------|
| book_loan（新建） | 借阅记录 | status ∈ {BORROWED, RETURNED}；同书在借唯一（应用层拦截）；字段级见附录A §2 |
| employee（现存只读） | 员工信息（联查展示） | PK oprid；字段级见附录A §1 |

### 5.3 关键数据约束与语义

1. `updated_at` 由应用层显式写入（禁止依赖 ON UPDATE 隐式刷新）；
2. 逾期不落库——按 `due_date` 实时计算（§三.4），避免存储冗余状态；
3. borrower_oprid 关联 employee.oprid 为**应用层关联**（跨库，不做物理外键）。

## 六、服务与集成需求

### 6.1 服务能力划分

| 能力域 | 覆盖能力 |
|--------|---------|
| 借阅台账 | 借出登记 / 归还 / 清单分页查询（含逾期计算与员工联查） |
| 通知编排 | 借出/归还后调 OA 推送（附录B）——失败不阻断主流程 |

### 6.2 关键行为要求（强制）

1. **归还幂等**：对 status=RETURNED 的记录再次归还 → 返回成功（幂等），不产生二次状态变更；
2. **重复借出拦截**：登记时存在同 book_id 未归还记录 → 拒绝（业务错误 message 明确）；
3. **OA 失败不阻断**：借出/归还的主事务提交后异步调 OA 推送；失败仅记日志（最终一致，可人工重试）——**禁止因 OA 不可用导致登记失败**；
4. **联查不落冗余**：清单查询实时联查 employee（不冗余存储姓名——员工改名跟随）；
5. **越权防护**：无多角色体系；但接口必须校验登录态，禁止匿名访问。

### 6.3 外部系统集成

- **OA 消息推送**（外部既有系统，**不开发**）：契约、鉴权与集成要求见**附录B**——借出/归还两个时机各发送 1 条提醒消息。

## 七、非功能需求

### 7.1 安全（强制）

1. OA 密钥/地址仅存配置中心（§九），**禁止**入代码/文档/日志；
2. 登记表单输入服务端校验（长度/日期合法性），防 SQL 注入（参数化查询）。

### 7.2 可用性（强制）

1. 异步操作有 loading；错误可读（展示后端 message）；空态有引导文案；
2. 防重复提交（按钮 loading）；归还二次确认。

### 7.3 性能

1. 清单分页加载（10/20/50 档位）；employee 联查批量反查（避免 N+1）。

### 7.4 兼容性

- 现代浏览器（Chrome/Edge 近两年版本）；构建 target 默认即可。

## 九、运行配置契约（★）

> 配置也是接口——键位一次冻结；**禁止实现期自创键名**。坐标结构定义如下（值以环境为准；密钥只在环境）。

### 9.1 键名表

| 键 | 含义 | 默认 | 环境覆盖 | 敏感 |
|----|------|------|---------|------|
| `app.port` | 服务端口 | 8310 | 是（生产由环境指定） | 否 |
| `db.hr.url` / `db.hr.username` / `db.hr.password` | HR 库连接（只读账号） | 无（必填） | 是 | password=是 |
| `db.app.url` / `db.app.username` / `db.app.password` | 本应用库连接 | 无（必填） | 是 | password=是 |
| `oa.base-url` | OA 服务地址 | 无（必填） | 是 | 否 |
| `oa.psk` | OA 预共享密钥 | 无 | 是 | **是** |
| `oa.psk-header-name` | 密钥请求头名 | `X-Internal-Key` | 是 | 否 |

### 9.2 环境坐标

- 配置源：Nacos（复用现有环境）——**结构**: {地址 / 命名空间 / Group / DataID}，具体值由环境供给（§十 就绪标准）；
- 本地开发：以上键可由本地 profile 提供（仅限 dev，`app.port` 等非敏感项）。

### 9.3 敏感值通道（强制）

- `db.*.password` 与 `oa.psk` **只存配置中心**（或运行时环境注入）——禁入代码/文档/日志/前端；
- OA 密钥**永不下发前端**（服务端进程内持有并注入出站请求头）。

### 9.4 覆盖优先级

`环境配置 > 本地默认`（方向显式：环境值总是覆盖本地）。

### 9.5 失败策略

- 关键配置（db/oa.base-url）拉取失败 → **启动失败并显式告警**（禁止静默降级/空值启动）；
- OA 密钥缺失 → 启动告警；运行时调用失败按 §六.2-3 处理。

## 十一、验证手段矩阵（★）

> 规则：**存在可运行环境时，验收面不得低于 L2**。级别：L0 构建 → L1 静态 → L2 启动冒烟（能启动 + 关键链路探活）→ L3 集成联调（真库/真 OA 数据面）。

| 验收项（引 §八） | L0 构建 | L1 静态 | L2 启动冒烟 | L3 集成联调 | 证据形式 |
|------------------|--------|---------|-------------|------------|---------|
| §8.1-1 借阅看板功能 | `npm run build` 零错误 | 红线自检（直调 axios/命名口径/硬编码密钥） | 服务启动（:8310）+ 清单接口探活返回 200 壳 | 真库借出→归还链路 | 构建日志 / 自检记录 / 接口响应 |
| §8.2-1 借还主链路 | 构建零错误 | — | 登记/归还接口壳正确（含幂等重复提交） | 真发 OA 两条提醒；重复归还幂等 | 接口响应 / OA 消息截图 / 服务日志 |
| §8.3 质量门禁 | 构建零错误 | 四项红线逐条核查 | — | — | 构建日志 / 核查记录 |

**缺环境处置**：L3 不可达（OA 白名单未就绪等）→ 挂起登记该项，交付物标注"待联调验证"；**禁止**以 L0/L1 结果冒充 L2/L3。
