       │          ├──▶ 本应用库（book_loan 读写）——借阅记录

## 2. 借还链路与逾期机制

### 2.1 借出链路

```
登记提交 → 后端校验（员工存在 / 同书未归还 / 日期合法）
        → 落库 book_loan（status=BORROWED）
        → 事务提交后异步调 OA send（LIB_BORROW；失败记日志）
        → 前端刷新清单
```

### 2.2 归还链路

```
归还提交（二次确认）→ 幂等检查（已归还则直接成功）
        → 置 status=RETURNED + return_date=今天
        → 事务提交后异步调 OA send（LIB_RETURN）
        → 前端刷新（从在借视图移除）
```

### 2.3 逾期判定（不落库）

```
筛选"逾期" 或 清单渲染时：
  overdue = (status=BORROWED) AND (due_date < 今天)
  overdue_days = 今天 - due_date
（服务端计算并返回；前端仅渲染——判定逻辑单一权威）
```

## 3. 设计原则

1. **只读优先**：HR 库严格只读，联查实时化（不冗余姓名，改跟随）；
2. **失败不阻断**：通知类外部调用与主业务解耦（异步 + 日志）；
3. **单一权威**：逾期判定只在服务端实现；状态枚举全项目唯一；
4. **最小授权**：DDL 授权仅限 book_loan 新建。

## 4. 速查表

| 联动关系 | 实现方式 |
|----------|----------|
| 借阅记录 → 员工 | borrower_oprid 应用层关联 employee.oprid（跨库无物理外键） |
| 借出/归还 → 通知 | 事务提交后异步调附录B §2.1（幂等 request_id） |
| 逾期展示 | 服务端计算 overdue/overdue_days → 前端渲染红色高亮 |
| 同书唯一在借 | 服务层拦截（status=BORROWED 且同 book_id 存在 → 拒绝） |
