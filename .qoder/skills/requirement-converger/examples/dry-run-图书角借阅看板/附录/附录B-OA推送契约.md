# 附录B：OA 消息推送外部契约

> **定位**：OA 消息推送是**外部既有系统**——本包**不开发**它。本应用（前端 + 后端）按本文档契约与其对接。
> **服务职责**：接收消息发送请求、按员工 oprid 投递提醒、提供送达状态查询。
> **对接方职责**：按契约实现调用（含时机与异常处理——见 §3 集成时序）；凭据由环境提供。
> **传输基线**：HTTP + JSON；服务地址与密钥由部署环境提供（本包不内置，禁止硬编码）。
> **配套材料**：本附录为《图书角借阅看板需求文档》的附录B。

---

## 1. 鉴权与通用约定

1. **鉴权**：**预共享密钥请求头**（密钥由环境提供；请求头名默认 `X-Internal-Key`，可配置——§九 键位表）+ 服务出口 IP 白名单（OA 侧配置）；
2. **统一响应**：`{status, data}`（业务错误 `status=error` + message）——⚠️ 与本应用壳 `{code, message, data}` **不同，转发时需转换，禁止混用**；
3. **超时建议**：发送类 10s；查询类 10s；
4. **幂等性**：发送端点按请求方生成的 `request_id` 幂等（同 request_id 重复调用返回首次受理结果）。

---

## 2. 端点契约（2 个）

### 2.1 消息发送（借出/归还登记事务提交后调用）

- **端点**：`POST {OA服务地址}/api/oa/message/send`
- **请求**：`oprid`（接收人员工账号，必填）、`template_code`（消息模板：借出=`LIB_BORROW` / 归还=`LIB_RETURN`）、`params`（模板变量：书名 book_name、应还日期 due_date 等）、`request_id`（调用方生成 UUID——幂等键）
- **返回**：`{status: "ok", data: {message_id}}`
- **调用方注意**：异步通知语义——失败不阻断借阅主流程（主事务已提交），失败记日志（可人工重试）。

### 2.2 送达状态查询（运维排查用；非主链路）

- **端点**：`GET {OA服务地址}/api/oa/message/{message_id}`
- **返回**：`{status: "ok", data: {message_id, delivery_status: DELIVERED|PENDING|FAILED}}`
- **调用方注意**：仅用于排查与人工重试核对；不参与业务判定。

---

## 3. 集成时序（本应用动作 → 调用端点 → 时机/异常要求）

| 本应用动作 | 调用端点 | 时机/异常要求 |
|-----------|---------|--------------|
| 借出登记成功（事务提交后） | 2.1 send（LIB_BORROW） | **异步**通知；失败仅记日志（登记不回滚） |
| 归还成功（事务提交后） | 2.1 send（LIB_RETURN） | 同上；重复归还（幂等命中）**不重复发送** |
| 运维排查 | 2.2 查询 | 按 message_id 查询送达状态 |

---

## 4. 对接注意事项（编号）

1. **双层响应结构**：OA `{status,data}` ≠ 本应用 `{code,message,data}`——后端转发层按各自协议转换；
2. **幂等可重入**：send 按 request_id 幂等——重试安全；重试仅限发送失败场景，≤1 次；
3. **异步语义**：登记接口不等待 OA 结果（异步语义）；"发送请求已提交"≠"已送达"（送达以 2.2 查询为准）；
4. **一致性边界**：OA 通知为**最终一致**（失败可容忍、可人工重试）；借阅登记主数据为强一致（本库事务）；
5. **地址与凭据**：OA 地址 / 密钥 / IP 白名单由部署环境提供——本包不内置，禁止硬编码（§九 通道 + §十 就绪标准）。
