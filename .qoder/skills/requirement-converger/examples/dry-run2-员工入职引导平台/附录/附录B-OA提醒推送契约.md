# 附录B：OA 提醒推送契约（外部系统）

> 定位声明：OA 消息推送为**外部既有系统**（**不开发**）——本平台仅作为**对接方**调用；服务职责与调用方职责分列如下。
> 传输基线：HTTP/JSON；地址与预共享密钥 **= 环境供给**（§九 通道；禁硬编码）。
> 配套材料：主文档《员工入职引导平台需求文档》v1.0。

## 1. 鉴权与通用约定

- **鉴权方式**：预共享密钥请求头（头名默认 `X-Internal-Key`，可配置——§九）；调用方出口 IP 需在 OA 白名单内（§十.3 就绪标准）；
- **统一响应结构**：`{status, data}`——**与本地壳 `{code, message, data}` 不同**——转发层**必须转换**，禁止混用（转换规则：OA `status==="ok"` → 本地成功；否则本地业务失败 + `data.fail_reason` 映射）；
- **超时建议**：发送类端点连接 5s / 读 10s；状态类端点连接 5s / 读 5s；
- **幂等性总述**：发送端点按 `idempotency_key` 幂等——相同键重复请求**不产生重复消息**，返回首次结果。

## 2. 端点契约（2 个）

### 2.1 发送提醒（配对通知 / 任务提醒 / 材料驳回——同一端点）

- 端点：`POST {oa.base-url}/api/oa/message/send`
- 请求（字段级）：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| receiver_oprid | string | 是 | 接收人工号 |
| message_type | string | 是 | `PAIRING_NOTICE` / `TASK_REMINDER` / `MATERIAL_REJECTED` |
| content | string | 是 | 消息正文（≤500 字） |
| idempotency_key | string | 是 | **幂等键——使用本平台提醒记录 id**（重推同键不重发） |
| sender_app | string | 是 | 固定 `ONBOARDING`（来源标识） |

- 返回：`{status: "ok" | "error", data: {message_id, fail_reason?}}`
- 约束/处理（服务侧行为——调用方不可假设的部分）：
  - 受理≠送达：`status=ok` 仅表示受理成功，终态以 2.2 查询为准（**异步语义**）；
  - 相同 `idempotency_key` 重复调用返回首次 `message_id`。

### 2.2 查询送达状态

- 端点：`POST {oa.base-url}/api/oa/message/status`
- 请求：`{idempotency_key}`（或以 `message_id` 查询——二选一，实现按 OA 实际能力对接）
- 返回：`{status: "ok", data: {message_status: "SENT" | "FAILED", fail_reason?}}`
- 失败原因枚举（可读映射）：`UNREACHABLE`（不可达）/ `AUTH_FAILED`（鉴权失败）/ `RATE_LIMITED`（限流）——本平台落库 `reminder_log.fail_reason`。

## 3. 集成时序

| 本平台动作 | 调用端点 | 时机/异常要求 |
|-----------|---------|--------------|
| 配对创建成功（含任务实例生成） | 2.1 发送提醒（配对通知） | **事务提交后异步**触发；失败不阻断配对（入 FAILED 可重推） |
| 任务临近截止（调度或人工触发——实现自定，仅定义行为） | 2.1 发送提醒（任务提醒） | 异步；幂等键按（提醒记录 id）；失败不阻断主流程 |
| 材料审核驳回 | 2.1 发送提醒（材料驳回） | 审核事务提交后异步；失败不阻断审核结果 |
| 记录页重推（FAILED → 重推） | 2.1 再次发送（**同 idempotency_key**） | 幂等保证不重复；成功/失败回写 reminder_log |
| （后台兜底）送达状态核对 | 2.2 查询送达状态 | 可轮询核对自己 PENDING 的提醒（实现自定频率） |

## 4. 对接注意事项（编号）

1. **双层响应结构**：OA `{status,data}` ↔ 本地 `{code,message,data}`——转发层转换，禁止混用（§1）；
2. **幂等可重入**：幂等键=提醒记录 id——重推安全（§2.1）；
3. **异步语义**：受理≠成功——终态以本平台 reminder_log 状态为准（与 OA 回执核对）；
4. **一致性边界**：提醒推送**最终一致**（可容忍失败与重推）；配对/审核/任务数据为**强一致**（本平台事务内）——**禁止**因 OA 不可达导致主流程失败；
5. **地址与凭据**：`oa.base-url` / `oa.psk` / `oa.psk-header-name` 全量经环境供给（§九），禁止硬编码/写文档/下发前端。
