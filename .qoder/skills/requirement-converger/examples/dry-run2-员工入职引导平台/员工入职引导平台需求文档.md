## 一、项目背景与目标

### 1.1 系统定位

员工入职引导的内部管理平台：HR 管理员配置入职任务模板并按岗位为新人自动生成任务清单，跟踪完成进度；入职材料（身份证/学历/合同扫描件）线上提交与审核归档；导师分配可视化（含带教负载）与配对互评；培训课程登记与 OA 提醒推送。现状痛点：纸质检查表易丢漏、导师分配无负载视图、培训签到靠 Excel 且提醒靠人工。

```
[HR 管理员] ─┐
[部门主管]  ──┼──浏览器──▶ [入职引导平台（本应用: 前端+后端）]
[员工]     ─┘                  │           │              │
                    [HR 库 employee 只读] [平台库 10 表读写] [OA 提醒推送（外部）]
```

### 1.2 用户角色

| 角色 | 可做什么 | 不可做什么 |
|------|---------|-----------|
| HR 管理员 | 全部页面；任务模板配置、材料审核、导师库/配对、课程与提醒管理 | 修改 HR 库数据 |
| 部门主管 | 入职进度看板（**仅本部门**）；查看本部门新人材料审核状态（只读） | 配置模板 / 审核材料 / 配对管理 |
| 员工（导师/新员工） | 配对评价页（**仅本人参与的配对**）；查看本人任务清单（只读） | 访问其余管理页面 |

### 1.3 建设范围（9 个页面 / 4 域）

| # | 业务域 | 页面名称 | 路由 | 说明 |
|---|--------|---------|------|------|
| 1 | 引导任务 | 任务模板配置 | `/onboarding/task-templates` | 按岗位维护任务模板（CRUD + 启用/停用） |
| 2 | 引导任务 | 入职进度看板 | `/onboarding/progress` | 新人任务进度跟踪（按状态/部门筛选） |
| 3 | 材料管理 | 材料审核台 | `/onboarding/material-review` | 待审材料队列：通过/驳回（含原因） |
| 4 | 材料管理 | 材料归档查询 | `/onboarding/material-archive` | 已归档材料检索（按新人/类型/时间） |
| 5 | 导师配对 | 导师库管理 | `/onboarding/mentors` | 导师登记与带教负载视图 |
| 6 | 导师配对 | 配对管理 | `/onboarding/pairings` | 新人与导师配对（负载提醒 + 解除/重建） |
| 7 | 导师配对 | 配对评价 | `/onboarding/feedback` | 配对到期互评（导师↔新人双向） |
| 8 | 培训提醒 | 培训课程管理 | `/onboarding/training` | 课程登记/发布/停用与报名名单 |
| 9 | 培训提醒 | 提醒推送记录 | `/onboarding/reminders` | OA 提醒发送记录与失败重推 |

### 1.4 交付物要求

| 交付物 | 要求 |
|--------|------|
| 前端工程 | 可构建（`npm run build` 零错误） |
| 后端服务 | 9 页面对应 API、任务生成与提醒编排能力（含幂等与失败处置） |

## 二、总体要求

### 2.1 技术栈（强制）

| 层 | 技术 | 版本要求 | 用途 |
|----|------|---------|------|
| 前端框架 | Vue 3（`<script setup>`） | ^3.5 | 全部页面 |
| UI 组件库 | Element Plus | ^2.13 | 全部交互组件 |
| 构建 | Vite | ^8 | dev / build |
| 状态管理 | Pinia | ^2 | 用户信息/权限 |
| 后端框架 | Spring Boot + MyBatis-Plus | 2.7.x | API 与数据访问 |
| 数据源 | HR 库（只读）+ 平台库（读写） | 现存/新建 | 双源，见 §五 |
| OA 推送 | 外部系统（不开发） | — | 按附录B 对接 |

### 2.2 部署形态（强制）

1. 独立部署，网关路径 `/onboarding/`；前端路由 base `/onboarding/`；
2. 开发端口：dev `8410`（`npm run dev`）；生产端口见 §十（留白 L4）；
3. 接口寻址：前端不含 baseURL（同源相对路径）；dev 态 Vite 代理 `/api` → 后端；
4. 后端形态：Spring Boot 单服务（双数据源 dynamic-datasource）。

### 2.3 架构红线（强制）

1. 页面组件**禁止**直调 `axios`/`fetch`——所有 HTTP 请求经 API 封装层；
2. 前后端交互字段一律 `snake_case`；
3. 统一请求层完成响应拆包（见 §三.3）——调用方禁止双重解包；
4. 材料文件下载**必须**服务端鉴权流式转发（不暴露直链）——见 §三.6。

### 2.4 构建命令与质量门禁

| 命令 | 说明 |
|------|------|
| `npm install` / `npm run dev` | 安装 / 本地开发（:8410） |
| `npm run build` | 生产构建（零错误为门禁底线） |
| `mvn -B test` | 后端单测（全绿为门禁底线） |

**质量门禁**：构建报错修复 2 次仍失败 → 挂起求助，严禁带病交付。

## 三、全局机制需求

### 3.1 认证与 Token（强制）

- 复用宿主免登接入（宿主携带 token 进入 `/onboarding/`）——URL token 提取后**无痕净化**（replace，不产生历史记录）；请求层统一注入 `Authorization: Bearer {token}`；
- 401 → 清 token + 提示 + 跳转登录失效页；请求进行中 401 同样收口。

### 3.2 权限体系（强制）

- **角色模型**：`SUPER_ADMIN`（HR 管理员，全量）/ `DEPT_MANAGER`（部门主管，本部门数据）/ `EMPLOYEE`（员工，本人数据）；
- **数据范围隔离**（隔离键机制——本项目为部门×人员维度，替代模块维度）：
  - 主管：服务端按登录人所在部门过滤（部门归属以 employee 现网字段为准——见留白 L3），只见本部门新人的任务/材料只读视图；
  - 员工：仅本人工单（任务清单只读、本人参与的配对与评价）；
- **校验流程**：token 有效 → 角色判定 → 数据范围二次校验（服务端强制，前端菜单/按钮配合隐藏）；
- **状态码口径**：未登录 401 / 无权 403（"权限不足"）/ 参数错误 400——业务错误恒 200（见 §三.3）。

### 3.3 统一响应约定（强制）

- 业务响应壳：`{code, message, data}`；`code===200` 视为成功并拆包返回 `data`；业务错误 HTTP 状态恒为 200，由 message 承载原因；
- HTTP 错误映射：401 → 登录失效处置；403 → "无权访问"；其他 → 网络异常兜底提示；
- 分页结构：`{ total, current_page, list }`（全平台唯一分页口径）；
- 写操作返回：成功返回受影响主键或 `true`；业务拒绝返回 code≠200 + message（如"该新人已有生效配对"）。

### 3.4 枚举与常量（强制）

| 对象 | 枚举 | 说明 |
|------|------|------|
| 任务状态 `task_status` | `PENDING` → `IN_PROGRESS` → `DONE` | 终态 DONE；不可逆 |
| 材料状态 `material_status` | `SUBMITTED` → `APPROVED` / `REJECTED`（驳回后可重新提交回到 SUBMITTED） | REJECTED 需 reason |
| 配对状态 `pairing_status` | `ACTIVE` → `CLOSED` | CLOSED 后不可再评价 |
| 评价方向 `feedback_direction` | `MENTOR_TO_NEWCOMER` / `NEWCOMER_TO_MENTOR` | 每方向至多 1 条 |
| 课程状态 `course_status` | `DRAFT` / `PUBLISHED` / `DISABLED` | 仅 PUBLISHED 可报名 |
| 提醒状态 `reminder_status` | `PENDING` / `SENT` / `FAILED` | FAILED 支持重推 |

### 3.5 消息与交互规范（强制）

- 保存/审核成功 `ElMessage.success`；业务错误展示后端 message；
- 高风险操作（驳回、解除配对、停用课程）需二次确认；提交按钮请求期间禁用 + loading；
- 列表空态 `el-empty`；加载 `v-loading`；表格分页 10/20/50 档位。

### 3.6 敏感数据与留痕（强制·隐私红线）

- 材料文件（身份证/学历/合同）**列表接口不返回文件内容**（仅元数据：类型/文件名/大小/上传时间/状态）；
- 文件下载 = 服务端鉴权（角色+数据范围）后**流式转发**——**禁止**返回直链或对象存储裸 URL；
- 材料审核（通过/驳回）与下载动作**必须写操作日志**（谁/何时/对谁的材料——审计留痕；落表见 §五）；
- 密钥/口令只存配置中心（§九），禁入代码/文档/日志。

## 四、功能需求

### 4.1 引导任务域

#### 4.1.1 任务模板配置（`/onboarding/task-templates`）——HR 专用

**定位**：按岗位维护入职任务模板（新人任务实例的生成依据）。

**布局结构**：顶部操作区（岗位筛选 + 启用状态筛选 + 新建按钮）→ 模板表格 → 新建/编辑抽屉（基本信息 + 任务条目动态列表）。

**功能区规格**：

| 控件/列 | 数据源/行为 |
|---------|------------|
| 列：模板名称/适用岗位/任务数/状态/更新时间 | 直出；任务数=条目数 |
| 列：操作 | 编辑 / 启用停用切换 |
| 抽屉：模板名称 | 必填，唯一（重名拒绝） |
| 抽屉：适用岗位 | 下拉（岗位字典——实现可内置常量表，键值声明于 §九） |
| 抽屉：任务条目 | 动态列表：任务名称（必填）/说明/截止天数（正整数，相对入职日）——至少 1 条 |

**状态机**：模板 启用 ⇄ 停用（二态）；表格查询 loading。

**关键交互流程**：
1. 新建/编辑：抽屉填写 → 保存 → 校验（重名/条目≥1/天数正整数）→ 成功后关闭并刷新；
2. 停用：确认后置停用（**仅影响后续实例生成，不影响已有实例**）；
3. 重新启用：恢复可生成态。

**业务规则**：
- 模板名称全局唯一；任务条目数 ≥ 1；截止天数 ≥ 1；
- **快照语义**：修改模板不影响已生成的任务实例（实例为生成时快照）；
- 停用模板不再参与新实例生成，但可重新启用。

**数据依赖**：onboarding_task_template CRUD（§五）。

#### 4.1.2 入职进度看板（`/onboarding/progress`）

**定位**：新人任务进度跟踪（HR 全量 / 主管本部门只读）。

**布局结构**：筛选区（部门下拉/任务状态/关键字）→ 新人进度表格 → 行展开任务明细（只读）。

**功能区规格**：

| 控件/列 | 数据源/行为 |
|---------|------------|
| 筛选：部门 | HR：全部部门；主管：锁定本部门（下拉禁用） |
| 列：新人姓名/部门/入职日期 | employee 联查（只读） |
| 列：导师 | 生效配对导师（无则 “—” ） |
| 列：任务完成度 | `n/m` + 进度条（服务端计算） |
| 列：材料状态 | 待审 n / 通过 n（汇总） |
| 行展开：任务明细 | 任务名称/状态/截止日/完成时间（按模板顺序，只读） |

**状态机**：无（只读查询）。

**关键交互流程**：筛选 → 查询 → 行展开 → 查看明细。

**业务规则**：主管数据范围=本部门（服务端强制）；完成度= DONE 数/总数（总数 0 显示 0/0）；任务明细按模板条目顺序。

**数据依赖**：onboarding_task + employee 联查 + onboarding_pairing。

### 4.2 材料管理域

#### 4.2.1 材料审核台（`/onboarding/material-review`）——HR 专用

**定位**：入职材料审核队列（通过/驳回）。

**布局结构**：状态 tab（待审/已通过/已驳回）→ 材料表格 → 预览抽屉（元数据 + 下载 + 审核操作）。

**功能区规格**：

| 控件/列 | 数据源/行为 |
|---------|------------|
| 列：新人/材料类型/文件名/大小/提交时间/状态 | 元数据直出（**不含文件内容**） |
| 抽屉：下载按钮 | 服务端鉴权后流式下载（见 §三.6） |
| 抽屉：通过/驳回操作 | 仅待审状态可操作；驳回弹窗：原因必填（≤200 字） |

**状态机**：`SUBMITTED → APPROVED / REJECTED`；驳回后新人重新提交 → 回到 `SUBMITTED`（重申计数+1，展示于抽屉）。

**关键交互流程**：
1. 审核：打开预览 → 下载查阅 → 通过（确认）/驳回（填原因）→ 成功后刷新队列；
2. 驳回后：新人在外部提交新版本 → 本台重新出现待审。

**业务规则**：仅待审可操作；驳回原因必填；**审核与下载均写操作日志**（§三.6）；列表不返回文件内容（隐私红线）。

**数据依赖**：onboarding_material + 文件存储（实现自定，仅接口定义）+ 操作日志表（§五）。

#### 4.2.2 材料归档查询（`/onboarding/material-archive`）

**定位**：已归档（通过）材料检索与下载。

**布局结构**：筛选区（新人/材料类型/通过时间区间/关键字）→ 表格 → 下载。

**功能区规格**：列（新人/类型/文件名/通过时间/审核人/操作[下载]）；仅 `APPROVED` 出现在本页。

**状态机**：无（只读）。

**关键交互流程**：筛选 → 查询 → 下载（鉴权+留痕）。

**业务规则**：主管可见本部门（只读）；下载校验角色+数据范围；下载留痕。

**数据依赖**：onboarding_material。

### 4.3 导师配对域

#### 4.3.1 导师库管理（`/onboarding/mentors`）——HR 专用

**定位**：导师登记与带教负载视图。

**布局结构**：筛选（部门/状态）→ 导师表格 → 新建/编辑弹窗。

**功能区规格**：

| 控件/列 | 数据源/行为 |
|---------|------------|
| 列：姓名/工号/部门/擅长领域 | 直出 |
| 列：当前带教数 | **实时计算**（该导师 ACTIVE 配对数） |
| 列：状态 | 启用/停用切换（停用确认） |

**状态机**：导师 启用 ⇄ 停用。

**关键交互流程**：新建（工号校验存在且唯一）→ 保存；停用 → 确认 → 置停用（不影响已有 ACTIVE 配对，但不可再被选为新配对导师）。

**业务规则**：同员工唯一导师记录；工号必须存在于 employee（只读校验）；带教数实时计算不入库。

**数据依赖**：onboarding_mentor + employee 校验 + pairing 计数。

#### 4.3.2 配对管理（`/onboarding/pairings`）——HR 专用

**定位**：新人与导师配对（**入职启动点**：配对成功自动生成任务实例并推送提醒）。

**布局结构**：tab（生效中/已解除）→ 配对表格 → 新建配对弹窗（选新人 → 选导师，导师下拉**显示当前带教数**）→ 解除确认。

**功能区规格**：

| 控件/列 | 数据源/行为 |
|---------|------------|
| 列：新人/部门/导师/配对起始日/状态 | 直出（新人部门 employee 联查） |
| 新建：新人下拉 | 未关联 ACTIVE 配对的新人（按岗位匹配模板预览） |
| 新建：导师下拉 | 启用中导师 + `（带教 n 人）` 负载提示；**负载≥阈值（默认 5）给黄色提示但不阻断** |
| 列：操作 | 生效中→解除（确认）；已解除→只读 |

**状态机**：`ACTIVE → CLOSED`（解除）。

**关键交互流程**：新建配对 → 保存 → **同一事务内：① 生成任务实例（模板快照）② 写入提醒记录（配对通知，附录B）** → 提交后异步推送 OA → 刷新。

**业务规则**：
- **同新人同时至多 1 个 ACTIVE 配对**（后端拦截）；
- 任务实例生成与配对同事务（强一致）；OA 推送为提交后异步（**失败不阻断配对**，失败入重推队列）；
- 解除需确认；解除后不可评价（§4.3.3）。

**数据依赖**：onboarding_pairing + onboarding_task 生成 + onboarding_reminder_log + OA（附录B §2.1）。

#### 4.3.3 配对评价（`/onboarding/feedback`）

**定位**：配对互评（导师↔新人双向，各 1 条）。

**布局结构**：配对列表（HR 全量 / 员工仅本人参与）→ 评价抽屉（星级 1-5 + 文本 ≤500 字 + 提交）。

**功能区规格**：列（新人/导师/状态/我的评价状态/对方评价）；抽屉：星级+文本提交；已提交方向只读展示。

**状态机**：配对 `ACTIVE` 可评价（存在 `CLOSED` 后评价被禁）；方向独立（每方向至多 1 条）。

**关键交互流程**：选择配对 → 填星级+文本 → 提交 → 刷新；已提交不可修改/删除。

**业务规则**：评价不可修改/删除；方向互评独立；展示规则按留白 L5（默认实名）。

**数据依赖**：onboarding_feedback + pairing。

---

### 4.4 培训提醒域

#### 4.4.1 培训课程管理（`/onboarding/training`）——HR 专用

**定位**：课程登记/发布/停用与报名名单管理。

**布局结构**：筛选（状态/时间区间）→ 课程表格 → 新建/编辑抽屉 → 报名名单抽屉（手工登记）。

**功能区规格**：列（课程名/讲师/时间/地点/名额/已报名/状态/操作）；操作：编辑（DRAFT）/发布/停用/名单。名单抽屉：添加员工（工号）、移除、总数与名额实时对账。

**状态机**：`DRAFT → PUBLISHED → DISABLED`（DRAFT 可编辑；PUBLISHED 仅可停用）。

**关键交互流程**：
1. 新建（DRAFT）→ 发布（确认）→ 可登记报名；
2. 报名登记：名单抽屉添加工号（校验存在、去重、**名额上限**）→ 保存；
3. 停用：确认 → 不可再登记（已登记保留）。

**业务规则**：仅 PUBLISHED 可登记；报名数 ≤ 名额（拦截）；同一人工号不重复登记；PUBLISHED 后时间/名额不可改（只能停用重建）。

**数据依赖**：onboarding_course + onboarding_enrollment + employee 校验。

#### 4.4.2 提醒推送记录（`/onboarding/reminders`）——HR 专用

**定位**：OA 提醒发送记录与失败重推。

**布局结构**：筛选（状态/提醒类型/时间区间）→ 记录表格 → 失败行“重推”按钮。

**功能区规格**：

| 控件/列 | 数据源/行为 |
|---------|------------|
| 列：提醒类型/接收人/内容摘要/创建时间/发送时间/状态/失败原因 | 直出（失败原因来自 OA 回执） |
| 列：操作 | FAILED→重推（确认）；其他状态只读 |

**状态机**：`PENDING → SENT / FAILED`；FAILED → 重推 → `PENDING`（重申计数+1）。

**关键交互流程**：重推（确认）→ 置 PENDING 并异步调用 OA（**幂等键=提醒 id**，不产生重复消息）→ 刷新看终态。

**业务规则**：重推幂等（附录B §2 幂等键）；失败原因必须展示（可读映射：不可达/鉴权失败/限流）；记录不可编辑删除。

**数据依赖**：onboarding_reminder_log + OA（附录B §2.1/§2.2）。

1. `updated_at` 由应用层显式写入（**禁止**依赖 ON UPDATE 隐式刷新）；

5. 操作日志（onboarding_operation_log）只增不改不删（审计用途）；
6. 跨库关联（task/pairing → employee.oprid）为**应用层关联**（跨库无物理外键）。

## 六、服务与集成需求

### 6.1 服务能力划分

| 能力域 | 覆盖能力 |
|--------|---------|
| 引导任务 | 模板 CRUD/启停；任务实例生成（配对触发）；进度聚合查询 |
| 材料管理 | 材料提交接收/审核流转/归档检索/鉴权下载/操作留痕 |
| 导师配对 | 导师 CRUD/启停；配对创建解除（含任务生成与提醒编排）；带教负载计算 |
| 培训提醒 | 课程 CRUD/发布停用；报名登记与名额校验；提醒发送/重推/记录查询 |

### 6.2 关键行为要求（强制·编号）

1. **配对唯一性**：同新人同时至多 1 个 ACTIVE 配对（后端拦截，并发场景需唯一兜底）；
2. **入职启动三件套**：配对创建 = ① 任务实例生成（模板快照）② 提醒记录写入 ③ 通知推送（异步）——① ② 与配对同事务（强一致），③ 提交后异步（**失败不阻断**，入 FAILED 可重推）；
3. **OA 幂等**：推送按幂等键（提醒 id）——重推不产生重复消息（附录B §2）；
4. **材料隐私**：列表不返文件内容；下载=鉴权流式转发；审核/下载写操作日志（§三.6）；
5. **数据范围强制**：主管/员工的数据范围在**服务端**过滤（前端隐藏仅为体验）；
6. **名额校验**：报名登记先查后写防超额（并发需唯一兜底）；
7. **负载提示**：配对创建时导师负载≥阈值（§九键位）仅黄色提示**不阻断**（阈值可配）；
8. **驳回闭环**：驳回原因必填回写入材料表；重提后回到 SUBMITTED（重申计数+1）；
9. **联查不落冗余**：新人姓名/部门等实时联查 employee（不冗余存储）；
10. **越权拦截**：所有接口校验登录态+角色+数据范围（禁止匿名访问）。

| 外部系统 | 角色 | 契约 | 凭据 |

| OA 消息推送 | 对接方（**不开发**） | 附录B（2 端点） | 环境供给（§九 通道） |
| HR 库 | 只读数据源 | 附录A §1 | 只读账号（§十.3） |
| 配置中心（Nacos） | 配置供给 | §九 坐标结构 | 运行时注入 |

## 七、非功能需求

### 7.1 安全（强制）

1. OA 密钥/库口令仅存配置中心（§九），禁入代码/文档/日志；
2. 材料文件（身份证/学历）属敏感数据：列表不返内容、下载鉴权+留痕（§三.6）；
3. 表单输入服务端校验（长度/日期/枚举），参数化查询防 SQL 注入；
4. 下载接口防越权：对象标识不得可枚举遍历（校验归属）。

### 7.2 可用性（强制）

1. 异步操作 loading；错误可读（展示后端 message）；空态引导（el-empty）；
2. 高风险操作二次确认（驳回/解除配对/停用课程/重推）；
3. OA 不可达时：配对/任务主链路不受影响（异步隔离）——提醒页可见 FAILED 并可重推。

### 7.3 性能

1. 列表分页（10/20/50）；跨库联查批量反查（避免 N+1，employee 按 oprid 集合批量）；
2. 进度看板聚合查询走单 SQL（禁止逐人循环）；材料下载流式响应（不整文件入内存）。

### 7.4 兼容性

- 现代浏览器（Chrome/Edge 近两年版本）；构建 target 默认即可。

## 八、验收标准

### 8.1 功能验收清单（9 行——与 §一.3 页面一一对应）

| # | 页面 | 验收点 |
|---|------|--------|
| 1 | 任务模板配置 | 新建（重名拒绝/条目≥1校验）→ 启停切换 → 停用不影响已有实例 |
| 2 | 入职进度看板 | 完成度 n/m 正确；主管仅本部门；行展开明细按模板顺序 |

| 4 | 材料归档查询 | 仅 APPROVED 在列；下载鉴权（越权 403）；下载留痕 |
| 5 | 导师库管理 | 工号唯一；带教数实时准确；停用后不可被配对 |
| 6 | 配对管理 | 同新人唯一 ACTIVE；配对后任务实例+提醒记录同事务生成；解除确认到位 |
| 7 | 配对评价 | 每方向至多 1 条；提交后不可改；CLOSED 后禁评 |
| 8 | 培训课程管理 | 发布后可登记；名额满拦截；PUBLISHED 不可改时间/名额 |
| 9 | 提醒推送记录 | FAILED 可重推（幂等无重复）；失败原因可读 |

### 8.2 关键端到端场景验收

1. **入职启动主链路**：新建配对 → 任务实例按模板生成 → 配对通知推送（OA 收到）→ 进度看板可见新人及 0/m 进度 → 任务推进至 DONE 后进度实时变化；
2. **材料审核闭环**：新人提交材料 → 审核台待审 → 驳回（含原因）→ 重提 → 通过 → 归档页可查 → 下载成功且留痕（越权他人下载被 403）；
3. **培训提醒闭环**：建课→发布→登记至满额（第 11 人被拦截）→ 提醒推送 → 人为断网重推场景验证 FAILED→重推→SENT 幂等。

### 8.3 构建与质量门禁

1. `npm run build` 零错误；2. `mvn -B test` 全绿；3. 无页面直调 axios/fetch；4. 字段命名 snake_case 一致；5. 无硬编码密钥/TODO 占位符。

### 8.4 交付物清单

1. 前端工程（可构建）；2. 后端服务（含任务生成与 OA 异步编排）；3. 10 张表建表脚本（唯一 DDL）；4. 接口契约与部署说明。

## 九、运行配置契约（★）

> 配置也是接口——键位一次冻结；**禁止实现期自创键名**。坐标结构定义如下（值以环境为准；密钥只在环境）。

### 9.1 键名表

| 键 | 含义 | 默认 | 环境覆盖 | 敏感 |
|----|------|------|---------|------|
| `app.port` | 服务端口 | 8410 | 是 | 否 |
| `db.hr.url` / `db.hr.username` / `db.hr.password` | HR 库连接（只读账号） | 无（必填） | 是 | password=是 |
| `db.app.url` / `db.app.username` / `db.app.password` | 平台库连接 | 无（必填） | 是 | password=是 |
| `oa.base-url` | OA 服务地址 | 无（必填） | 是 | 否 |
| `oa.psk` | OA 预共享密钥 | 无 | 是 | **是** |
| `oa.psk-header-name` | 密钥请求头名 | `X-Internal-Key` | 是 | 否 |
| `onboarding.load-threshold` | 带教负载提示阈值 | 5 | 是 | 否 |
| `onboarding.file-upload.max-size` | 材料文件大小上限（MB） | 20 | 是 | 否 |

### 9.2 环境坐标

- 配置源：Nacos（复用现有环境）——**结构**: {地址 / 命名空间 / Group / DataID}，具体值由环境供给（§十 就绪标准）；
- 本地开发：非敏感键可由本地 profile 提供（仅限 dev）。

### 9.3 敏感值通道（强制）

- `db.*.password` 与 `oa.psk` **只存配置中心**（或运行时环境注入）——禁入代码/文档/日志/前端；
- OA 密钥**永不下发前端**（服务端进程内持有并注入出站请求头）。

### 9.4 覆盖优先级

`环境配置 > 本地默认`（方向显式：环境值总是覆盖本地）。

### 9.5 失败策略

- 关键配置（db/oa.base-url）拉取失败 → **启动失败并显式告警**（禁止静默降级/空值启动）；
- OA 密钥缺失 → 启动告警；运行时推送失败按 §6.2-2 入 FAILED 可重推。
