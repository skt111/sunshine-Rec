## 使用建议

### 作为 AI Agent 任务输入

1. **阅读顺序**: 主文档（§一~三 全局）→ §四 功能需求（按域并行拆分）→ 附录（按需查阅）；
2. **任务拆分参考**: 9 个页面天然划分为 **4 个业务域 + 基础设施 = 5 个可并行工作流**（见下）；域间唯一真实依赖 = W0 共享资产；
3. **验收依据**: 主文档 §八（验收清单 + 端到端场景 + 构建门禁）+ §十一（验证手段矩阵）。

### ★ 可并行工作流划分线索

| 工作流 | 域 | 含页面/模块 | 可并行性 | 依赖 |
|--------|-----|------------|---------|------|
| W0 基础设施 | 工程骨架 / 认证接入 / 请求层 / 权限体系 | 工程搭建、token 接入、请求封装、布局框架、角色权限 | **必须最先** | — |
| W1 引导任务域 | 任务模板 / 进度跟踪 | 任务模板配置、入职进度看板 | 可并行 | W0 |
| W2 材料管理域 | 材料审核 / 归档 | 材料审核台、材料归档查询 | 可并行 | W0 |
| W3 导师配对域 | 导师库 / 配对 / 互评 | 导师库管理、配对管理、配对评价 | 可并行 | W0 |
| W4 培训提醒域 | 课程 / 提醒 | 培训课程管理、提醒推送记录 | 可并行 | W0 |

> 共享资产提示: 统一请求层、认证接入与**角色权限体系**被全部页面引用——必须在最早波次交付；OA 客户端封装被 W4 与 W1（任务提醒）共同引用——归属 W0 或最早消费波次；W1-W4 四域互相独立，可四路并行。

## 硬约束（🚨 红线——可直接转化为审计检查项）

- 🚨 **HR 库只读**：employee 表**严禁写入/DDL**；本次**唯一 DDL 授权 = 新建 10 张表**，其余严禁任何 DDL；
- 🚨 **OA 为外部系统（不开发）**：仅按附录B 契约对接；地址与密钥由环境供给，**禁止硬编码**；
- 🚨 **接口自行设计**：本包不含既有实现坐标；前后端接口由开发方设计并冻结为契约；
- 🚨 **隐私红线**：入职材料（身份证/学历/合同）属敏感数据——**列表不返回文件内容**、下载需权限校验、操作留痕；密钥/口令**只存配置中心**；
- 🚨 **架构红线**：页面组件禁止直调 axios/fetch（必须经 API 封装层）；前后端字段命名 snake_case；统一响应壳见 §三.3。

## 需求覆盖范围（速览——数量与主文档一致）

- **页面**: 9 个 / 4 域（引导任务 ×2、材料管理 ×2、导师配对 ×3、培训提醒 ×2）
- **技术栈**: 前端 Vue 3.5 + Element Plus；后端 Spring Boot 2.7 + MyBatis-Plus + 双数据源
- **数据表**: 11 张（新建 10 + 现有只读 employee）
- **外部对接**: OA 提醒推送 2 端点（附录B）；HR 库（只读）；配置中心（Nacos）
- **角色**: HR 管理员 / 部门主管 / 员工（导师与新员工共用员工视角，权限细分见 §三.2）
- **验收**: §八 功能验收清单（9 行）+ 端到端场景 + §十一 验证手段矩阵（L0-L3）
