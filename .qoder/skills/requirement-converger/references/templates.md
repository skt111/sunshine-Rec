## 1. 通用写作规则（十条纪律）

1. **行为级描述，不写既有实现坐标**——路径/函数名/内部机制命名一律去除（防照抄）；确需留白处显式声明"接口由开发方自行设计"；
2. **数量处处可对数**——页面/表/端点/验收项在 README 速览、主文档清单、验收清单三处数量一致；
3. **🚨 标记硬约束**——负面清单置顶 + 关键规则标"（强制）"；
4. **状态机/枚举显式**——状态名、流转、终态、映射表全部写死（如 `draft ⇄ published`、状态码 0-6 映射）；
5. **数据契约分层到底**——L1 字段级必做（字段名/类型/约束/默认值/说明/索引/唯一键）；**L2 关系级/L3 口径级按触发分级生成**（见 §4）；配置到 键名/含义/默认/坐标；
6. **契约六要素**——外部对接必含: 端点 / 请求响应 / 调用时序 / 一致性等级 / 幂等键 / 安全通道与失败策略；
7. **命名口径统一并声明**——如"前后端交互一律 snake_case；前端内部可 camelCase"；
8. **版本单源化**——文档头: 版本号 + 生成日期 + 配套材料；下游引用本包时携带版本；变更走变更记录节；
9. **留白显式**——"可自行设计 vs 必须对齐"逐项标注（汇总于自检报告）；
10. **每事实一处权威**——状态机定义在主文档；附录只引不抄（如附录C 注"具体需求以主文档与附录A/B 为准"）。

## 3. 主文档模板（§一~§十一）

> 文档头必含: 文档性质（自包含声明）/ 版本号 / 生成日期 / 配套材料清单 / 模式声明（如"库表只读""外部系统不开发"）。

### §一 项目背景与目标
- 系统定位（一句话 + 架构图: 端/层/数据源/外部系统）
- 用户角色（枚举 + 各自职责）
- **建设范围（可枚举表）**: `| # | 业务域 | 页面名称 | 路由 | 说明 |`——行数=页面总数（三处一致）；
- 交付物要求表（前端工程/后端服务/数据库/文档——明确各交付物的验收形态）。

### §二 总体要求
- **技术栈（强制）**: 每端一张表（层/技术/版本要求/用途）——版本锁定；
- 部署形态（强制）: 独立/增量、路由 base、接口寻址（代理/网关）、开发端口、环境变量表、构建产物与分包、兼容目标；
- 工程组织（建议）与**架构红线（强制）**: 如"页面组件禁直调 axios（必须经 API 封装层）""路径别名禁止深层相对引用""响应拆包契约单一实现"；
- 构建命令与质量门禁表（命令/说明 + "构建零错误"熔断红线）。

### §三 全局机制需求
> 全部页面的公共基础。逐机制小节（按实际情况裁剪但不得缺"认证/权限/响应壳/隔离键"四项）：
- 认证与 Token（来源/提取存储/白名单/兜底拦截/请求注入/过期处理——编号写死）；
- 权限体系（模型/校验流程含状态码口径 400/401/403/数据归属二次校验/前端配合）；
- 隔离键机制（如 module_code 全栈贯穿链路）；
- 统一请求层与响应约定: **响应壳 `{code, message, data}` + 业务错误 HTTP 状态口径 + 错误映射表 + 分页结构（多套必须区分）+ 写操作返回值口径**；
- 数据级联机制（级联链 + 特殊规则如"选中数>1 时下游禁用并清空"）；
- 页面布局框架（结构/菜单/初始化顺序——敏感步骤标"严禁乱序"）；
- 安全（水印/XSS 消毒/Token 无痕净化）；
- 消息与交互规范（成功提示/危险确认/行级 loading/空态/轮询三重防护参数）；
- 类型与常量约定（**枚举全表** + 状态机初值/终态；时间格式化统一口径）。

### §四 功能需求
> 按域 → 页面展开。每页面固定七要素（缺一不可）：
1. **定位**（一句话 + 路由）；
2. **布局结构**（页面分区示意链）;
3. **功能区规格**（**字段级表格**: 控件/列/数据源/行为——参照蓝本"筛选区规格/表格列规格"格式）；
4. **状态机**（前端 stage / 后端状态 的流转与终态）；
5. **关键交互流程**（编号步骤: 点击→请求→反馈→刷新）；
6. **业务规则**（编号——可静态核查的硬规则）;
7. **数据依赖**（所需能力清单——对应 §六 能力域；口径敏感查询指向附录A L3 编号）。

### §五 数据模型需求
- 数据源划分表（数据源/内容/读写边界）；
- 表清单按域（表名/用途/关键约束——数量可对数；字段级指向附录A）;
- 关键数据约束与语义（编号: 扩展规则/时间字段语义如"禁止 ON UPDATE 污染维护时间"/状态机/一致性约束如"主键与向量库 point_id 一致"）。

### §六 服务与集成需求
- 服务能力划分表（能力域 → 覆盖能力）;
- **关键行为要求（编号强制）**——如三明治事务/权限校验/归属校验/一致性校验/缓存编排/越权拦截/导出防护等（蓝本 10 条样式）;
- 外部系统集成清单（每个外部系统: 角色 = 对接方还是开发方 + 指向附录B + 凭据来源）。

### §七 非功能需求
- 安全（强制）/ 可用性与交互（强制）/ 性能（分页/懒加载/缓存/分包/大数据量防护/N+1）/ 兼容性——分小节编号。

### §八 验收标准
- **功能验收清单（按页面）**: `| # | 页面 | 验收点 |`——行数=页面总数；
- 端到端场景验收（编号: 跨页面/跨系统主链路，如"发布→检索生效""权限隔离"）；
- 构建与质量门禁（构建零错误/红线自检/命名一致/无 TODO 占位符/无硬编码密钥）；
- 交付物清单（编号——与 §一 交付物一致）。

### §九 运行配置契约（★ 新增——配置也是接口）
- **键名表**: `| 键 | 含义 | 默认 | 环境覆盖 | 敏感 |`——键位一次冻结，禁止实现期自创键名；
- **环境坐标**: 配置源（如 Nacos）地址/命名空间/Group/DataID 逐项列出（值可由环境供给，但**坐标结构必须定义**）；
- **敏感值通道**: 密钥/口令只存于 {配置中心/运行时注入}——禁入代码、禁入文档、禁入日志；
- **覆盖优先级**: 环境配置 > 本地默认（显式声明方向）；
- **失败策略**: 拉取失败必须显式告警/启动失败（不做沉默降级）——"静默失败最贵"；**失败策略实体化（V1.5.0）**: "必须显式告警/阻断"类条款须具可执行断言（启动/运行时自检）——纸面策略不计（无代码实体 = 未实现）；
- **接线清单（V1.5.0）**: 每项环境/外部资源一行——`| 资源 | 期望值 | 获取方式 | 落值动作 | 验证命令 | 责任方 |`；确认（可用/可提供）≠ 接线（已落值且验证命令通过）。

### §十 环境预备清单（★ 新增——环境也是需求）
- **连通性标准**（每依赖系统一行: 依赖 / 探测方式 / 就绪判定）——含**配置中心双通道探测**: HTTP 端口 + gRPC 端口（通常 +1000），两通道都通才算就绪；
- **端口清单**（dev/测试/生产 + 占用冲突处置: 先探后改——端口占用者身份核验，禁止盲杀进程）；
- **账号与权限就绪标准**（数据库账号/外部系统账号/IP 白名单/授权范围——"谁提供、什么算就绪"）;
- **环境差异项**（如编码要求 `-Dfile.encoding=UTF-8`、路径含中文时的启动参数）;
- 就绪判定汇总（全部依赖的就绪标准一览——不达标时的挂起规则）；
- **就绪时效（V1.5.0）**: 每项就绪声明带"实测于 YYYY-MM-DD"标识；执行/验证前须复检——就绪是时点事实，非常态属性（环境漂移防御）。

### §十一 验证手段矩阵（★ 新增——验收未定义验证手段=盲区）
- **验收项 × 验证级别 × 证据形式**:

| 验收项（引 §八 编号） | L0 构建 | L1 静态 | L2 启动冒烟 | L3 集成联调 | 证据形式 |
|----------------------|--------|---------|-------------|------------|---------|
| 页面 #1 | npm run build 零错误 | 红线自检 | 页面可达+关键接口探活 | 真实数据链路 | 构建日志 / 截图 / 接口响应 |

- **级别定义**: L0 构建（编译/打包零错误）→ L1 静态（规则自检/审计）→ L2 启动冒烟（能启动 + 关键链路探活）→ L3 集成联调（真环境数据面: 真库/真外部系统）；
- 🚨 **规则: 存在可运行环境时，验收面不得低于 L2**；
- **环境形态行（V1.5.0）**: 矩阵须含"环境/运行形态"维度——每条失败策略/降级行为必须有对应可验证行（正常形态 + 降级/受限形态行为对照 §九 失败策略）；防"策略写了没人验"；
- 每级缺环境时的处置（如 L3 不可达 → 挂起登记，禁静默跳过）。

## 4. 附录A 模板 —— 数据结构契约（三层 + 历史表专项 · V1.3.0）

> 数据访问契约完备性 = 实现侧（god）写 SQL 所需信息的全覆盖：**L1 字段级（Schema）+ L2 关系级（关联）+ L3 口径级（查询语义）**；历史表另加**专项**（使用面 DDL / 物理属性 / 核对脚本）。**按触发分级生成，不做无差别三层化**（防过度规定）。

### 4.1 触发分级（附录A 生成前先判定——本节为唯一权威）

| 需求场景 | 附录A 要求 |
|---------|-----------|
| 单表 CRUD 为主 | L1（字段级——现有格式） |
| **联查补全 / 聚合口径 / 派生状态** | L1 + L3 口径层；**凡表链涉及 ≥2 张表（含跨表聚合/派生、历史表参与）时另加 L2 关系层** |
| **历史建表接入（现存表读取）** | + **历史表专项**（使用面 DDL + 物理属性 + 核对脚本）；**历史表参与联查时，关系层 L2 须覆盖该关联** |
| 多库/跨源（如 MySQL⋈Oracle） | + 关系层 L2 **跨源标注**（应用层关联声明） |

> **"口径敏感"判定（L3 触发——聚合 / 派生状态 / 联查补全 三类）**：
> - 正例：带教负载=按 pairing ACTIVE 计数 → L3；完成度=DONE 数/总数 → L3；列表投影跨表拼 domain_name → L3；
> - 反例：单表按条件查询 / 单表分页 / 单表排序 → **不进 L3**（不判缺）。
> "明确 SQL"的正确形态 = **口径写死（语义层），执行形态不锁（物理层）**——参考 SQL 可执行但允许实现侧等价改写，**等价性以口径为准**。

````markdown

## 1. {域}（{数据源}）—— L1 Schema 层
### 1.1 {表名} — {中文名}
| 字段名 | 类型 | 约束/默认值 | 说明 |
|--------|------|------------|------|
| … | VARCHAR(64) | PK | … |
（枚举字段在说明中列举全部取值；外键/引用在说明中标注指向）

索引：{idx_*}。唯一键：{uk_*}。扩展列（{版本/来源}）：{…}。

## N. 表间关联关系 —— L2 关系层（触发分级见 §4.1）
| # | 关系 | 左表.列 | 右表.列 | 基数 | 连接语义 | 用途 | 物理注记 |
|---|------|---------|---------|------|---------|------|---------|
| R1 | {A↔B} | a.x | b.y | N:1 | LEFT JOIN | {业务用途} | {单库=索引现状；多库=跨源·应用层关联——无物理外键} |

## N+1. 查询口径 —— L3 口径层（触发：聚合/派生状态/联查补全——判定见 §4.1）
### Q1 {查询名}（{目的}）
- 表链: A ⋈ B ⋈ C（注明 INNER/LEFT 与连接列）
- 口径（伪 SQL）: SELECT {投影} FROM {表链} WHERE {过滤口径} GROUP BY {分组}
- 参考 SQL: {可执行 SQL——允许实现侧等价改写；等价性以口径为准}
- 排序/分页: {口径}
- 性能注记: {联查批量反查/禁 N+1/索引提示（建议非强制）}

## N+2. 历史表专项（触发：历史建表接入）
### H1 {表名}（{数据源}——现存表·只读）
- **使用面 DDL 摘录**（最小集——仅本次使用到的表×列×索引，非全量 DDL）
- **物理属性清单**: collation（{值或"核对项"}）/ 字符集 / 时区语义 / 自增形态 / 索引现状
- **核对脚本**（可执行·只读——获取真实结构最小集，先探后写；"可执行"= 可直接运行且返回待断言列）:
  ```sql
  -- 断言列/family/字符集（只读；先探后写）
  SELECT COLUMN_NAME, COLUMN_TYPE, COLLATION_NAME, CHARACTER_SET_NAME, IS_NULLABLE
  FROM information_schema.COLUMNS
  WHERE TABLE_SCHEMA={schema} AND TABLE_NAME={table} AND COLUMN_NAME IN ({used_cols});
  ```
- **演进/兼容注记**: 废弃列（{…}）/ 多义列（{…}）/ 只读约束（禁写入/DDL）
````

### 4.3 写作规则（三层通用）

- **来源标注**: 每张表注明提取途径（DDL 脚本 / 实体类反推 / 文档转载）——允许下游追溯；历史表标注"使用面摘录（现网核对后定稿）"；
- 新建表与现有表**必须分区标注**（如 §1 现有只读表 / §2 本次新建表）；
- 字段说明写"业务语义"而不只是类型（如 `is_super: 1-是（跳过所有权限校验）0-否`）；
- **L3 只写口径敏感的查询**（聚合/派生/联查补全三类——判定见 §4.1）——单表条件查询不进 L3（防过度规定）；
- **口径写死、执行形态不锁**：参考 SQL 允许等价改写，"等价性以口径为准"（防锁死实现 + 防双源失真）；
- **物理属性必写**（历史表与新库交接面）：collation / 字符集 / 时区——"collation 跨族"为实证 P0 类型（跨表列比较报 Illegal mix）;
- **核对脚本可执行**: 历史表的每项结构断言给出可直接运行的只读查询（骨架见 §4.2 H1）——"可执行"= 语句可在只读连接直接运行且返回待断言列（**非"见 DBA"类占位**；"先探后修"纪律延伸）。
