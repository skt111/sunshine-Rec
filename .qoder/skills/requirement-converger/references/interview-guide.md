# S1 澄清采访 · 问题清单与采访格式（需求文档收束器）

> 用途: S1 阶段的一次性澄清清单——九类问题 + 输出格式 + 追问规则 + 两类登记表。
> 依据: 长任务实验复盘 §2.4（留白显式）+ 蓝本采访经验（可枚举要求）。
> 版本: V1.4.1（本文件历次: V1.0 创建 → V1.3.0 I5 扩容 → V1.4.1 数据源获取路径）｜ V1.4.1: I5 增「获取路径四路分流」与探查产物分层处置（数据源获取引导）。

## 0. 三条铁律

1. **一次性输出完整清单**——禁止挤牙膏式零散追问；
2. **每问带标记**：【必答】/【可默认→默认值：...】/【必答（场景）】——【必答（场景）】= 场景命中时按【必答】处理（未命中不询问；场景判定依据须在采访记录注明）；未答项按默认推进，**不阻塞**；
3. **答案必须可枚举**——凡清单类问题（页面/表/端点/角色/外部系统）要求"数量 + 名称"，回答含"若干/几个/等等"必须回追一轮要求清单化。

## 1. 采访输出格式（呈现给用户的模板）

```markdown
【需求收束 · 澄清清单】（一次性完整版，可整段回复；未答项将按建议默认推进并登记留白）

I1 目标与角色
1.【必答】<问题>
2.【可默认→默认值：<默认>】<问题>
...

I2 功能与页面
...

（回复提示：按编号回复；标 ⏭ 表示该项走默认）
```

- 已从用户既有材料（PRD/记录/代码）能推断的项：先标注"已从 <来源> 获知：<推断>"，让用户只做确认或纠正，避免重复问；
- 全部问题一轮给完；用户可任意粒度回复。

## 2. 九类问题清单

### I1 目标与用户角色 → §一 背景目标

- 【必答】这个系统/功能解决什么问题？现状痛点是什么？
- 【必答】使用者有哪几类角色？各自能做什么、不能做什么（权限差异）？
- 【可默认→默认值：无宿主直接访问】有没有宿主/上级系统？入口从哪进（免登跳转/独立登录）？
- 【可默认→默认值：按 §八 验收全过】"做完"的标准是什么？

**可枚举要求**: 角色清单（数量+名称+权限差异）。

### I2 功能与页面清单 → §一 建设范围 + §四 逐页面

- 【必答】请按"页面/界面"逐条列出全部功能（名称 + 一句话说明）——**数量与名称必须齐全**；
- 【必答】每个页面上有哪些关键操作（增删改查/导入导出/批量/审批/下载）？
- 【可默认→默认值：由收束器推导】页面之间的跳转关系与入口？
- 【可默认→默认值：独立新工程】交付形态：独立工程，还是现有工程增量？
- 【必答】有没有**明确不做**的功能？（范围边界——进负面清单）

**可枚举要求**: 页面数=名称全表；此数量将在 README 速览 / §一 建设范围 / §八 验收清单三处保持一致。

### I3 域划分线索 → README【可并行工作流划分线索】

- 【可默认→默认值：由收束器主动建议】你倾向如何把页面分组为业务域？
- 【可默认→默认值：由收束器分析】哪些页面共享组件/数据（应同域或共享资产）？
- 【可默认→默认值：由收束器建议】哪些内容必须先完工（公共基础：工程/认证/请求层）？
- 【可默认→默认值：全部可并行】有没有已知的并行开发计划？

**说明**: 用户无意见时，由收束器主动给出域拆分建议（蓝本实证：此线索是最大效率来源，必须主动输出不得留空）。

### I4 技术栈与端 → §二 总体要求

- 【必答】涉及哪些端（前端/后端/外部系统/数据库）？哪些是从零开发、哪些是外部既有系统？
- 【必答】技术栈要求：框架与版本（强制 or 建议）？是否在现有工程内开发？
- 【可默认→默认值：构建零错误】构建命令与质量门禁（构建命令必须可得——写清楚）？
- 【可默认→默认值：随现有工程规范】字段命名口径、代码规范、语言版本？
- 【可默认→默认值：无兼容性要求】浏览器/系统兼容性要求？

**可枚举要求**: 端清单 + 每端技术栈表（锁定版本）。

### I5 数据 → §五 数据模型 + 附录A（三层契约）

- 【必答】有没有**新建表**？几张？每张表干什么？（可枚举）
- 【必答】有没有**现有表**要对接？（获取途径按下方「分流」判定——命中①②③即为途径明确）
- **获取路径分流（收束器动作——S1 前置“数据源能力盘点”后按序判定，命中即用）**:
  ① **项目已有数据库 MCP（只读）** → 收束器直接只读探查（information_schema：表/列/索引/collation 分布），产出 DDL 等效物；**探查产物分层处置**: 客观结构（字段/类型/索引/物理属性）直采入附录A（标注格式：`来源：MCP 只读探查（information_schema）｜日期：YYYY-MM-DD｜性质：客观结构`）；语义映射/口径推断 → 走“已从 <来源> 获知：<推断>”确认机制（本文档 §1）；示例值 → 探查限行脱敏样例或请用户提供（与下方敏感数据处理要求协同），**禁止编造示例**；
  ② **无 MCP → 请用户提供**: DDL 脚本 / 表结构文档（**历史建表场景**：提供“使用面”（本次用到的表×列）最小集即可，不要求全量 DDL）；
  ③ **现有工程增量 → 代码反推**（**无 MCP 时本路优先**——能反推则不劳烦用户，反推不可得再转 ②）: 既有实体类 / mapper XML·SQL / 库表映射注释（标注推断性质 → 走确认机制）；
  ④ **均不可得 → 降级**: 登记留白（必须对齐）+ §十 就绪标准（核对脚本模式）+ **绝不编造字段/坐标**（防幻觉纪律）。
  > **① 通道使能（可选引导·条件触发）**: 无 MCP 且用户可提供只读连接信息 → 引导配置数据库 MCP（四步：只读账号最小权限 → `.mcp.json`（server 启动 + 凭据仅经 `${VAR}` 禁明文 + 只读开关如 `ENFORCE_READ_ONLY_QUERIES=true`）→ 平台授权（`mcp__{server}__*`）→ 连通性试跑）；**建议不阻断**——不配置转 ②③④，配置成功回 ① 通道（一次配置全链复用）。
  > 深度探查（表清单核对闭环 / DDL 建模闭环）沿用 architect §1.8 数据源确认协议，不重复发明。
- 【必答（聚合/派生/联查场景）】有哪些表间关联/联查链路？聚合/派生/联查补全类查询是否已有**明确口径或参考 SQL**？（可得性：有现成 SQL / 口头口径 / 由收束器推导——落附录A L2/L3）
- 【可默认→默认值：单数据源】几个数据源（MySQL/Oracle/其它）？各存什么？跨源关联如何声明（应用层关联，无物理外键）？
- 【必答】数据读写边界：哪些只读、哪些可写？有没有"严禁 DDL"类约束？
- 【必答（历史表场景）】**物理属性**是否已知：collation / 字符集 / 时区？（实证：collation 跨族是联调期 P0——未知时写"核对脚本"进历史表专项）
- 【可默认→默认值：按现有规范】敏感数据（身份/薪酬）的处理要求（脱敏/审计）？

**可枚举要求**: 表清单（按域分组，数量可对数）；每张表的**字段级获取途径必须明确**（四路分流命中①②③即明确；MCP 探查/代码反推产物须标注来源与推断性质；否则登记留白）；**关系清单与口径查询清单**（多表/联查场景——数量可对数，落 L2/L3）。

### I6 外部依赖 → §六 集成 + 附录B

- 【必答】依赖哪些外部系统/接口？（清单）
- 【必答】契约可得性：有对接文档 / OpenAPI / 口头描述 / 需自行设计？——**接口契约可得性决定附录B 的写法**（有文档→固化转载；无文档→按最小契约占位并标注"必须对齐"）；
- 【可默认→默认值：由环境供给并要求写入 §九】鉴权方式（token/密钥/IP 白名单）？凭据从哪来（一律禁止硬编码）？
- 【可默认→默认值：同步调用+失败记日志】超时/重试/幂等/一致性要求（强一致 or 最终一致）？
- 【可默认→默认值：登记留白不阻塞】外部系统不可达时怎么办（挂起/降级/占位）？

**可枚举要求**: 端点清单（数量）；每个端点标注一致性等级与幂等键。

### I7 运行环境 → §九 运行配置契约 + §十 环境预备清单

- 【可默认→默认值：复用现有配置中心】配置从哪来（配置中心/环境变量/本地文件）？坐标是什么（地址/命名空间/Group/DataID）？
- 【可默认→默认值：由收束器给出并按现网调整】配置键命名（键名表）？敏感值通道（只存配置中心/运行时注入）？覆盖优先级（环境覆盖默认）？
- 【可默认→默认值：现有部署形态】部署形态与端口（dev/测试/生产各是多少）？网关前缀/路由 base？
- 【必答】账号/权限就绪标准：数据库账号、外部系统账号、IP 白名单由谁提供、什么算就绪？
- 【可默认→默认值：连通性=接口可访问+主链路探活通过】依赖系统连通性标准（含配置中心双通道探测：HTTP 端口 + gRPC 端口（通常+1000）——两通道都算就绪判定项）？

**说明**: 坐标/账号类敏感项用户常无法当场给出 → 登记留白（必须对齐），写"就绪标准"而非具体值。

### I8 约束与负面清单 → 硬约束置顶 + 负面清单节

- 【必答】严禁做什么（DDL/改现有功能/动生产数据/引入新依赖/覆盖他人文件）？
- 【可默认→默认值：无】性能约束（并发量/数据量级/导出上限）？
- 【可默认→默认值：按现有安全规范】安全红线（XSS/密钥不下发/水印/审计留痕）？
- 【可默认→默认值：无强制】合规/审计要求（操作日志、脱敏）？

**产出**: 负面清单（分类: 数据类/外部类/接口类/安全类），全文用 🚨 置顶；每条可直接转化为实现约束与审计检查项。

### I9 验收标准 → §八 验收 + §十一 验证手段矩阵

- 【必答】交付物清单（哪些产物算交付——可枚举）？
- 【必答】每个页面的验收点（可枚举——将形成验收清单行）？
- 【可默认→默认值：由收束器从 §四 推导】端到端关键场景（跨页面/跨系统的主链路）？
- 【可默认→默认值：构建零错误 + 审计 P0/P1=0】质量门禁（构建/测试/审计级别）？
- 【必答】有没有**可运行环境**（数据库/外部服务可达）用于启动冒烟与联调？——决定验证矩阵级别下限（有环境则 ≥L2）；
- 【可默认→默认值：页面截图+构建日志】验收证据形式（截图/日志/接口响应/录屏）？

## 3. 追问规则（最多两轮）

1. 第一轮追问：只追"清单化不达标"与"【必答】空缺"项；
2. 第二轮追问：只追"必须对齐"类留白（外部契约/表结构/坐标）——一轮无果即转"待确认"，写入 §十 就绪标准并交付（不阻塞）；
3. 禁止对已答项重复确认；禁止把开放讨论变成问卷轰炸（用户一次回复即进入生成）。

### 4.2 留白登记表

| # | 留白项 | 状态 | 影响面 | 处理方式 |
|---|--------|------|--------|---------|
| L1 | 接口路径与参数 | 可自行设计 | 前后端契约 | 由开发方设计后冻结为契约（文档声明） |
| L2 | 外部系统密钥 | 必须对齐 | 联调 | 环境供给（禁硬编码）；§九 通道 + §十 就绪标准 |
| L3 | 生产端口占用情况 | 待确认 | 启动 | §十 预检项：端口占用者身份核验 |
| L4 | 历史表物理属性（collation/字符集） | 必须对齐 | 数据访问 | 附录A 历史表专项：核对脚本 + 使用面 DDL（现网核对后定稿） |

> 状态三分法: **可自行设计**（显式授权开发方定）/ **必须对齐**（值或契约必须来自外部，缺失则挂起）/ **待确认**（有默认可推进，确认后修正）。
> 留白登记表最终随包交付（并入自检报告），保证"留白显式"。
