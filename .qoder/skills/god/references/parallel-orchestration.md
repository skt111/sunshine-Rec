# God 并行编排模式（--parallel）细则

> **配套**: `.qoder/rules/15-parallel-dev.md`（协议层——本细则的实现编排）+ god SKILL §参数说明 `--parallel`。
> **定位**: 单会话内多 worker 并行开发的完整编排流程（阶段 A-G），供主 Agent 逐步执行。
> **适用前提**: 父 plan 已拆分（children ≥2）且**拆分级别沙盘绿灯**（父 plan `sandboxRef` pass 或用户显式豁免）；子 plan 沙盘凭证由**阶段 B 执行/复用**（不要求前置已有——实证：部分历史子 plan 无独立沙盘凭证）；文件面矩阵核验通过。

---

## 0. 输入与前置

| 输入 | 来源 | 校验 |
|------|------|------|
| 父 plan + 子 plan 列表 | `plans.json` children（id/file/complexity/依赖） | children ≥2；**父 plan 沙盘凭证 pass（拆分级别绿灯）**；各子 plan 状态 active/in-progress；子 plan 沙盘凭证盘点（已有 → 阶段 B 复用；无 → 阶段 B 补跑） |
| 冻结契约 | `plans.json` 行 `contracts` 字段 + 契约目录（api-contract）相关文件 | 契约清单冻结（内容改动走 CR）；`contracts` 字段为空时从 plan 详情/需求基线补提取（实证填充率约 1/3） |
| 各子 plan 文件面 | plan 详情「任务拆解」+ 需求基线表清单 | **归一化为「主仓根相对路径」（逻辑路径基准——授权面/申报/变更清单三方统一）**；提取不完整风险由阶段 C「文件面申报」复核兜底 |
| 依赖关系 | 子 plan 依赖声明 + `children` 顺序 | 划分 wave（强依赖后置）；**存疑时保守串行**（宁慢勿撞） |
| 本域构建命令 | 01 §6.2 手动补位路由表（按文件面所属端推导） | 每子 plan 至少一条构建命令 |

**完成定义**: 全部子 plan done（含 auditor 审计通过）+ 汇聚验证通过（全量构建 + 场景级 + Playwright）+ 收口落盘。

**与 god 五阶段的映射（--parallel 变体语义）**:

| god 五阶段 | 并行模式对应 |
|-----------|-------------|
| 阶段 1 签名验证 | 父 plan 沙盘凭证校验 + 阶段 B 产出（/复用）各子 plan 沙盘凭证 |
| 阶段 2 上下文加载 | §0 输入提取（本表） |
| 阶段 3 编码实现 | 阶段 C（worker fan-out） |
| 阶段 4 构建验证 | 阶段 F（汇聚全量构建 + 场景级 + Playwright + 终审） |
| 阶段 5 跨端交接 | 阶段 G 收口（单会话内集成——无跨会话交接语义，跨端交接章节不适用） |

**检查点主体**: 编排级检查点以**父 planId** 命名（`checkpoint-{父planId}-{ts}.md`）；子任务级 TDD/场景记录可另附子 planId 检查点。

**启动动作（进入阶段 A 前）**: 父 plan status → in-progress 且 activePlan 指向父（god SKILL 流程同步）；children 出队时批量 active → in-progress。

**启动预检（Pre-flight——实验/首次运行前必做，哑任务先验证后放量）**:

| # | 探测项 | 方法 | 失败处置 |
|---|--------|------|---------|
| ① | **物理隔离实证** | 哑 worker 在其 worktree 写哨兵文件 → 主工作区对应路径断言未被改（直接回答 isolation 是否物理生效——路径基准探测） | 无隔离 → **fail-closed**（不进入 --parallel，回常规 god 逐 plan 串行） |
| ② | **路径语义实证** | pwd/branch 回传；哑 worker 写主仓绝对路径的越界行为（被拦 or 直写）；worktree 路径对主 Agent/审计体的可见性 | 越界不被拦 → 任务书强约束主区只读 + 汇聚对账依赖；可见性失败 → 审计物化交付（E/F）——**均属缓解路径，不触发 fail-closed** |
| ③ | **生命周期实证** | worker 返回后 worktree 保留/清理时机 | 自动清理不可控 → 改"返回前物化证据（diff/日志）到主区再允许清理" |
| ④ | **交互能力实证** | 首动作/中途消息能否到达主 Agent | 不支持中途 → CR 走"完成时携带"默认形态（阶段 D） |
| ⑤ | **并发与命名实证** | 2-3 哑 worker 并发行为 + 平台上限 + 命名实测（分支+目录两名） | 上限值回填检查点；命名回填（分支回传制锚点） |

预检结论必须回填检查点（实测值/失败处置）；① 号失败即 fail-closed，不得带病开跑。

## 阶段 A: 文件面矩阵核验（fan-out 前置闸门）

1. 从各子 plan 提取**文件清单**（将修改/新增的文件集合——**逻辑路径**）；
2. 生成**交叉矩阵**：两两比对，核查交集；
3. **判定**：
   - 交集为空 → ✅ 通过，进入步骤 3.5；
   - 存在交集 → 🚨 **不并行**（拆分质量问题）——将交集文件收归单一 owner（或标注串行段）后重新核验；无法收归 → 回 architect 复盘拆分（**修订的子 plan 走 revised 语义**：重评质量分 → 复验 → 回迁 active 后重进矩阵核验——x-rules 状态机）；
3.5 **契约依赖前置检查（前置拦截——替代事后 CR）**：凡子 plan 依赖声明含**跨边界接触面**（另一子 plan 的 API/数据面/消息/共享状态——判不准即视为触发，存疑保守）→ 校验其对应契约已入**冻结集**（冻结集 = `plans.json` contracts 条目 ∪ 契约目录中与该依赖面相关的文件；条目悬空指向不存在文件 → 视为缺失）；缺失 → 🚨 该子 plan **暂缓出队**——先由主 Agent 按 §0 参数链从 plan 详情/需求基线补提取并冻结；仍无法补齐 → 回 architect 补契约推演（**走 revised 语义——同步骤 3**；修订-重沙盘轮次计入熔断阈值；补推演后重进本步复检）——仍缺 → **标注串行段**（待依赖方波次完成后出队），串行标注并入步骤 5 产出（矩阵 + wave 计划）；
4. **wave 划分（依赖波）**：强依赖链（如配置域 → 知识域）分层——**wave 门定义: 该波全部子任务 E 通过 + 增量合入集成分支 + 该波范围验证通过 → wave N+1 从合并后基线起跑**（wave N+1 的 worker worktree 基于合并后分支创建；仅多波场景触发增量 merge——单波 = 现有 F.1 一次性 merge）；注意区分两类分批：**依赖波（wave）**涉及波间 merge，**执行分批（超并发上限）**仅为调度分批、不涉及 merge；
5. 产出：文件面矩阵 + wave 计划（写入检查点）。

> 判据来源：沙盘实践先例（"文件面不相交、无并行冲突"——历史沙盘审计行）。

## 阶段 B: 并行沙盘（per-子-plan 蓝军）

1. **凭证复用判定**: 已有独立沙盘凭证（子 plan `sandboxRef` pass）→ 直接引用（不重跑）；无凭证 → 补跑蓝军；
2. 补跑：对无凭证子 plan 启动只读蓝军（code-reviewer subagent，按 sandbox SKILL 的蓝军流程执行——报告规范唯一权威在 SKILL，本处仅登记编排增量：planId 显式传入、从零读取、P0/P1/P2 + REPORT-STATS）；可同时启动（相互独立）；
3. 蓝军报告由主 Agent 持久化到 `.qoder/skills/sandbox/reports/{date}-{planId}-{topic}-沙盘审计.md`；**本阶段是子 plan 沙盘凭证的产出点（/复用点）**——fan-out 前每个子 plan 必须有 pass 凭证；
4. P0 > 0 → 该子 plan 修订打回（不出队）；全绿（P0=0）→ 进入阶段 C；
5. **修订回流（A' 增量重核验）**：凡 B 修订触碰文件面/依赖的子 plan → 矩阵/wave 增量重算（记为 A'），任务书文件面以 A' 终版为准；矩阵记录来源 plan 的 `updated` 快照以识别失效。
6. **修复轮次记录（统一计数）**: 子 plan 修订-重沙盘轮次落「子 plan 详情修复轮次记录」节（与统一计数同载体）；**写入者 = 主 Agent**（worker 禁写易变资产）；父编排检查点账本行引用（追加式）。达上限处置见「熔断与降级」表。

## 阶段 C: worker fan-out（并行编码）

**按 wave 计划分批 fan-out**：wave N 全部子任务 **E 通过**（独立审计通过——阶段 E）且**波门满足**（增量合入集成分支 + 该波范围验证通过——见阶段 A-4）后，才启动 wave N+1；单波场景 = 一次性 fan-out（超并发上限时叠加执行分批——见本阶段并发控制；无波间 merge，归入 F.1 执行）。

**合批条款（同形小改——跨子 plan，V1.2.0——外部体系吸收）**

判据（统一口径）: 同一变更模式 ∧ **无独立审查面**（审查面 = 测试面 ∪ 判断面 ∪ 专项审查需求——任一命中即不合批）。
- 可合批示例: 多子 plan 各需同加一行日志埋点（同模式、审查可单 diff 统一覆盖）
- 不合批示例: 安全敏感文件同形修改（专项审查需求）；含定制措辞/判断类差异的目标
- 边界: 机械性差异（占位符/命名参数化——不构成独立审查面）→ 可合批，差异随任务书显式列出；内容性措辞定制/判断类 → 不合批

**批级承载协议（保底兼容——凭证链/逐 plan 审计不动）**:
1. 批任务书 = {子 plan 清单 + 各变更点（逐子 plan 标注）+ 授权面并集}
2. 批 worker 返回 = 各子 plan 独立 result 块（逐子 plan 承载 planId/files/commit/build）
3. 批级审查报告 = 单 diff 审查 + **子 plan 覆盖段表**（逐子 plan 审查结论——各子 plan done 的审计依据，对齐 F.6 终审先例）
4. done/修复轮次**逐一映射各子 plan**（批内某子 plan 问题 → 计该子 plan「修复轮次记录」）
5. CR 按子 plan 标注（`CR-{planId}-{seq}` 既有格式）；批级记录落父编排检查点

合批仅限**同波内**合并（波界不变）；实施前核验 15-parallel-dev.md / parallel-worker 定义的同步面。

对每个出队子 plan spawn 一个 `parallel-worker`（isolation: worktree 由平台托管），**任务书模板**如下：

```markdown
# 你是并行开发的编码 worker（子任务：{planId} — {planTitle}）

## 任务
- 子 plan 详情（最高执行宪法）: {plan 详情绝对路径}
- 需求基线锚点: {域引用 / 复用决策 / 表清单}
- 你的文件面（仅限）: {逻辑路径清单（主仓根相对——A' 终版矩阵条目）；禁止越界修改清单外文件}
- 冻结契约（只读消费）: {契约文件绝对路径列表}

## 环境
- 独立 worktree（平台已分配）——**首个动作: 报告 `pwd`（worktree 物理路径）与 `git branch --show-current`（实际分支）**
- 分支: 平台预绑定分支沿用；未绑定或可切换 → 切 `worker/{planId}`；**实际分支名以回传为准**
- **路径基准（逻辑路径）**: 授权面/申报/变更清单三方统一使用主仓根相对路径；**写域 = 你的 worktree 根（首动作 pwd 回传）拼接逻辑路径**；🚨 **主工作区（含绝对路径）只读——禁止任何主区写入与 refs 手术**（删分支/worktree remove 等）
- 🚨 命令/读写用绝对路径且必须落在自身 worktree 写域内（bash cwd 会在调用间重置——相对路径必失效）

## 执行要求
0. **文件面申报（第一步）**: 通读 plan 与相关代码后申报将修改/新增的完整文件清单（**逻辑路径**）——对照任务书「你的文件面」自查；需越界 → **停止受影响部分的修改**（其余继续），随完成返回携带 CR，不得先行修改
1. 按 plan「任务拆解」编码；每关键步骤后跑**本域**构建: {本域构建命令}（新 worktree 首次构建前先安装本域依赖——环境性失败不计入修复计数）
2. 遵循 15-parallel-dev.md: 不写易变资产（plans.json/契约/报告/检查点）；
   将要偏离契约或越界修改时——**停止受影响部分的修改**（其余继续），在完成返回的 cr 字段携带 CR（若预检④证实平台支持中途交互则即时上报）:
   `CR-{planId}-{seq}: {发起者（本 worker） | 涉及契约/文件 | 变更内容 | 影响面声明 | 紧急度}`（seq 含 worker 短标识或时间戳防并发撞号）
3. 完成即 commit（message 含 {planId} + 内容摘要）；禁止 merge 主分支
4. 场景矩阵自检（对照 plan「场景矩阵」逐项，未覆盖项在返回中声明）

## 返回格式（严格，主 Agent 按此解析）
[worker-result]
planId: {planId}
worktree: {worktree 物理路径}
branch: {实际分支名}
files-claimed: {开工申报文件清单}
files-changed: {实际变更文件清单}
commit: {hash}
build: pass/fail（命令 + 结果摘要）
self-check: {场景矩阵覆盖 n 项 / 未覆盖 m 项（列名）}
cr: 无 | CR-{...}（待仲裁：{内容}）
blockers: 无 | {描述}
summary: {≤10 行}
```

**申报复核（主 Agent）**: 申报 ⊆ 授权面 ∧ 各 worker 申报两两不相交（新增交集 → 按拆分质量问题升级：收归/串行/回 architect——与 15 §4 同口径）。

**依赖自举**: worktree 为新检出——worker 首次构建前先安装本域依赖（如 npm install）；**环境性失败（网络/安装）登记为环境失败，不计入"同一失败点修复 2 次"计数**（防假熔断）。

**并发控制**: **规模以实验首跑实测后定**（硬上限=平台并发实测值；预检⑤先跑 2-3 哑任务）；成本模型 = N×（worker+auditor+蓝军）+ 依赖自举 + merge/修复重派；超限执行分批（逐批登记）。**已知代价**: 全部 worker/auditor 返回经主 Agent 上下文（峰值载荷=落盘前）——N 较大时报告落盘后仅保留结构行与问题清单。

**角色-成本分级（V1.2.0——外部体系吸收）**

worker/auditor/蓝军派发原则:
- 机械转录类（计划含完整代码/直译型）→ 最低够用档；判断整合类（多文件协调/模式匹配）→ 标准档
- 终审与架构类 → 最强档；修复轮升级 → 不低于原档（对齐 x-rules.repairLoop escalation 精神）
- 原则: "turn count beats token price"（便宜档多轮未必省——总成本看轮次×单轮成本）

平台支持显式指定时遵此；不支持时以角色-任务匹配原则执行（不写死模型名——平台能力以实测为准）。

## 阶段 D: CR 仲裁（变更点单通道）

**交互模型**: 默认**"完成时携带 CR"**（worker 停止受影响部分的修改、其余继续、随完成返回上报——返工面=受影响部分；保守可执行）；若预检④证实平台支持中途交互，升级为实时上报。批准/驳回后由主 Agent **重派 worker 重入同 worktree** 执行（"广播"=下次任务书注入契约差分）。

1. worker 上报 CR → 主 Agent 仲裁（可调只读子代理——code-reviewer，平台无 Explore 类型以其替代——做影响面分析）；
2. **批准** → 主 Agent 更新契约基线（第 2 类资产写收口：仅主 Agent 写）+ **定向广播**给受影响 worker（新任务书附契约差分）；
3. **驳回** → worker **就地回退至原契约/文件面并留痕**，按原契约实现；
4. CR 记录按 **Ruling 三要素**（`Ruling: <决策> — <理由> — <若错代价>` + 来源=CR 仲裁 + 时间）落盘**检查点正文「裁决记录」节 + 执行账本行**（不新增目录）；
5. 🚨 worker 间禁止 P2P 沟通——所有跨 worker 协调经主 Agent 单通道。

## 阶段 E: auditor 流水线（fan-in 前置，独立审计）

**触发**: worker-N 返回且**达完态**（无待仲裁 CR、无 blockers、build pass）后**立即** spawn 该子任务的 auditor（流水化——不必等全部 worker 完成）；待仲裁 CR 先走阶段 D 裁决后再审计。

auditor 任务书要点：

```markdown
# 你是独立审计者（只读，复用 code-reviewer）。对 worker 产出从零审计

## 审计对象
- 审计对象（物化交付）: {主 Agent 物化的 diff 文本/变更清单（逻辑路径基准，落盘路径）} + {子 plan 详情绝对路径}（预期行为基准 = plan 场景矩阵 + 需求基线）
- 🚨 审计体不执行 git/shell——分支/diff 范围由调用方物化后传入（物化落盘: `.qoder/skills/audit/reports/.staging/`）

## 审计协议
- 独立性: 你是独立实例；不接受编码者上下文/假设；从零读取
- 报告规范唯一权威 = sandbox/audit SKILL（本任务书仅登记编排增量）；核对面: worker-result 仅列**待核验声明**——build 自报的权威复核点 = F 全量构建；引用自报须标注'自报（未独立复核）'；编排检查点（F.5 落盘/回填——终审前置）
- 分级: P0（各维度以 audit SKILL 权威清单为准——业务逻辑/规则流转/连带影响/数据对齐/DDL 一致性/场景覆盖）/ P1 / P2
- 每条: 【问题】【证据（文件:行）】【建议】
- 尾部结构行（必须）: REPORT-STATS: plan_id={planId} P0={n} P1={n} P2={n} VERDICT={pass|fail}
  （P0=0 且 P1=0 → pass；否则 fail）
- 返回报告全文（由主 Agent 持久化——只读审计体无写工具）
```

**结果处理**:
- P0 > 0 → 回 worker 修复（同一失败点修复尝试上限 2 次；2 次均未通过 → 该 worker **熔断**置 blocked 并报告）；
- P0=0 且 P1>0 → 询问用户是否修复（P1 裁量归用户）；
- 通过 → 主 Agent 持久化报告到 `.qoder/skills/audit/reports/audit-{planId}-{date}-{topic}.md`（签名: `audit_agent: "code-reviewer(subagent)"`）。

## 阶段 F: 汇聚与集成验证（fan-in）

1. **合并前校验与 merge 顺序**: 先对每 worker 分支执行**机械校验（判据公式）**——`git diff --name-only {base}..{branch}`: (a) 集合 ⊆ 授权面（逻辑路径基准）；(b) ∩ 资产黑名单（plans.json/契约/报告/检查点）= ∅；(c) == files-changed；(d) commit 为 base 后代（防历史改写）；主工作区侧 `git status` 哨兵对账（无越界写）——亦覆盖"驳回后就地回退"真实性验证；任一项不符 → 该 worker 产出打回（违规按拆分/纪律问题处置）。随后 merge: 各 worker 分支 → 集成分支（或主工作区）——由主 Agent 执行（`git merge` 或 `cherry-pick` 按分支拓扑取简）；冲突 → 回阶段 A 复盘（禁止现场硬解）；
2. **全量构建**: 按改动端逐端执行（mvn compile / uv run pytest / npm run build）；
3. **场景级验证**: 对照各子 plan 场景矩阵逐项闭环（01 §6.3）；
4. **Playwright 验证**: 查 context 目录的 e2e 黄金路径登记（e2e-golden-paths.md）——存在则按登记方式执行（浏览器截图 + 断言清单）；缺失不阻断；
5. **证据落盘与回填（终审前置——时序修正）**: 编排检查点补「场景验证记录」小节（矩阵行级）+ 回填各子 plan 详情「验证证据」节（三态结论 + 检查点引用）——**证据就绪后方可终审**（audit 判据要求核对面在审计时点可达）；
6. **终审 audit（集成态）**: 在证据落盘后 spawn 终审蓝军——a) 审计对象（物化）: 集成态 diff 文本/变更清单（主 Agent 物化落盘——审计体不执行 git）+ 各子 plan 详情（预期基准）+ 全量验证记录；b) 输出协议与 E 同构（REPORT-STATS；**plan_id={父planId}**，报告内列子 plan 覆盖表）；c) **失败闭环**: P0>0 → 集成态修复（主 Agent 最小修复或新建修复 worker）→ 重跑全量构建 → 终审重审；同一失败点修复尝试上限 2 次（2 次均未通过 → 父 plan 熔断 blocked）；d) 通过（P0=0 且 P1=0）→ 主 Agent 写各子 plan status=done（逐一）+ 持久化报告；
7. 通过后才允许合入主分支（🚨 裸 merge——worker 完成即合——是负增益，禁止）。

## 阶段 G: 收口

1. **plans.json 收口状态流转**: 全部 children done（终审通过——F.6d 写入）→ **父 plan done**（写入者=收口主 Agent/审计通过方代写；语义边界: 父 plan 无独立审计对象）；**activePlan 联动**: 若指向已 done plan 须改指（validate #1 强制）；updated 同步；**机械兜底**: `node .qoder/plans/validate-plans.js` 0 error（不依赖 Hook——多写者场景最后兜底）；
2. **检查点落盘**: `.qoder/skills/audit/checkpoints/checkpoint-{父planId}-{ts}.md`（编排级）——含文件面矩阵（A' 终版）/ wave 计划 / CR 记录 / worker 结果摘要 / auditor 报告引用 / **场景验证记录** / 闲置 worktree 标注；
3. **验证证据引用校验**: 终审前置回填已在 F.5 完成——本步仅做引用可达性校验（检查点 ↔ 各子 plan「验证证据」一致）；
4. **父详情「并行编排记录」回填**: 父 plan 详情增轻量节（引用式）——run 参数 / children 结果表 / 检查点与终审报告引用 / 降级登记；
5. **闲置 worktree 生命周期**: 超时/异常保留的 worktree → 检查点标注待查 → 收口阶段向用户提交**人工裁决**（保留/移除）——🚨 禁止平台自动清理误删待查证据；裁决结果落盘；
6. 汇报（含降级登记与遗留项）。

## 熔断与降级

| 触发 | 动作 |
|------|------|
| 同一失败点修复尝试 2 次均未通过 | 该 worker 熔断 → blocked + 人工介入（不影响其他 worker） |
| 子 plan 修复轮次达上限（`x-rules.repairLoop.maxRoundsParallel`=2；与统一计数同载体） | **escalation 对齐**: 输出裁决清单（Ruling 三要素）+ 该子 plan 置 blocked + 升级人工（**不自动收敛**——不再静默熔断；回转见 recovery blockedResolve②） |
| **集成态终审失败 ≥2 次** | **父 plan 熔断 → blocked + 人工介入**（集成态恢复路径） |
| CR 无法仲裁（影响面超父 plan） | 暂停受影响 wave → 上报用户 |
| worktree 物理隔离不可用（预检①失败——哨兵探测无隔离） | **fail-closed**: 不进入 --parallel——回常规 god 逐 plan 串行（无隔离不并行；登记原因） |
| worker 挂起/超时 | 检测: 阶段等待超阈值 → 干预（询问/终止）；终止后 worktree 保留待查（对照预检③）；平台超时行为以预检为准 |
| 平台并发上限 | 执行分批（超限部分按批调度——非依赖波，不涉 merge） |

## 场景矩阵（编排自身）

| 类别 | 场景 | 预期行为 | 验证方式 |
|------|------|---------|---------|
| 正常 | N=2-3 文件面不相交子 plan | 全流程闭环（A-G） | 实验首跑记录 |
| 异常 | worker 构建失败/CR 频发 | 熔断路径 + CR 单通道不重叠 | 条款核验 |
| 极限 | N 超过并发上限 | 执行分批（登记） | 分批登记核验 |
| 空值 | 无子 plan / 单子 plan | 参数校验拦截 → 回常规 god | 参数判定核验 |
| 并发 | 两 worker 触碰同文件 | 阶段 A 矩阵拦截；运行中发现 → CR | 双条款核验 |
| 权限 | worker 试图写易变资产 | 收口纪律禁止 + 汇聚校验 | 资产收口核验 |
| 超时 | worker 无响应 | 主 Agent 超时策略（询问/重试/终止）+ worktree 保留待查 | 超时条款 + 预检③ |
