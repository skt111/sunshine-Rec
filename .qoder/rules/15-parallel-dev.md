# 单会话并发开发协议 (Single-Session Parallel Development Protocol)

> **定位**: 本规则是**流程·横向协议**（编号 15 为流程协议扩展段，非端级规则）——适用于所有子系统的"单会话内多 worker 并行开发"场景。
> **上游**: 设计背景见本仓 harness 迭代记录（或相关 plan 详情）；平台事实基线：Qoder IDE subagent 无 Agent 工具 / 平台支持 `isolation: worktree`。
> **消费方**: god `--parallel` 编排（主）、parallel-worker agent、sandbox/audit 蓝军（旁路复用）、plans 状态机（收口面）。

---

## 1. 适用场景与前置条件

| 维度 | 说明 |
|------|------|
| **适用** | 单会话内由主 Agent 编排多个编码 worker subagent 并行开发；长任务（≥2 个文件面不相交的子 plan） |
| **不适用** | 共享基础设施改造（router/request/layout 等公共依赖——必须先行串行）；跨模块契约热点变更（单一 owner 处理）；单 plan 任务（并行无收益，走常规 god） |
| **前置条件** | ① 父 plan 已拆分（children ≥2）且**父沙盘凭证 pass（拆分级别绿灯，或用户显式豁免）**；② 子 plan 沙盘凭证由阶段 B 执行/复用（**不要求前置已有**——实证：部分历史子 plan 复用父凭证）；③ 文件面矩阵核验通过（两两不相交）；④ worktree 能力可用（否则走降级路径 §9） |

## 2. 角色拓扑（扁平兄弟模型 — flat siblings）

```
主 Agent（编排者 / 契约仲裁者 / 易变资产唯一写者）
├── worker-N（编码，isolation: worktree，各自独立分支）    ← 由主 Agent spawn
├── auditor-N（独立审计，只读，复用 code-reviewer）        ← 由主 Agent 在 worker 完成后 spawn（非 worker 内嵌套）
└── 蓝军（sandbox，只读，per-子-plan）                     ← 由主 Agent 在 fan-out 前 spawn
```

🚨 **审计必须由主 Agent 顶层 spawn**（扁平兄弟）——worker 与 auditor 是兄弟关系而非父子关系；禁止 worker 内嵌 subagent 自审（IDE 侧不支持 + 扁平独立性更强）。审计独立性硬要求：**编码者 ≠ 审计者实例，零上下文传递，从零读取**。

## 3. 资产写收口（核心纪律）

**易变资产四类**（唯一权威 = 主工作区主 Agent）：

| 资产 | worker 禁止行为 | 主 Agent 动作 |
|------|----------------|--------------|
| `plans.json` | 禁止写（含状态/updated） | 汇总时统一写（子 plan 状态流转） |
| 契约目录（api-contract） | 禁止写 | CR 仲裁批准后更新 + 定向广播 |
| 报告目录（sandbox/audit reports） | 禁止写 | 蓝军报告由主 Agent 持久化（只读审计体无写工具） |
| 检查点（checkpoints/） | 禁止写（含 CR 记录载体） | 阶段落盘检查点 + CR 记录 |

worker 的产出（代码/构建结果/报告片段）一律**通过返回值回传**，由主 Agent 落盘。🚨 **汇聚机械校验（编排 F.1 判据公式）**: 对每 worker 分支 `git diff --name-only {base}..{branch}`——(a) ⊆ 授权面（逻辑路径基准）；(b) ∩ 资产黑名单（四类）= ∅；(c) == files-changed；(d) commit 为 base 后代；主区 `git status` 哨兵对账——亦覆盖"驳回就地回退"真实性验证。

## 4. worker 分支与 commit 规范

1. **分支回传制**：优先 `worker/{planId}`（如 `worker/task-001`——平台托管 worktree 未预绑定分支或允许切换时）；平台预绑定分支则沿用——**实际分支名以 worker-result 回传为准**（汇聚 merge 与审计追溯以回传值为锚）；
2. worker 完成即 commit（message 含 planId + 子任务标识），失败可 reset；
3. **禁止 worker 直接 merge 主分支/主工作区**——merge 是主 Agent 汇聚验证后的动作（§编排 F 阶段）；
4. **文件面申报-复核闭环**：worker 开工第一步申报完整文件面（**逻辑路径**——主仓根相对）；主 Agent 复核公式 = **申报 ⊆ 授权面 ∧ 各 worker 申报两两不相交**（超出授权 → CR/挂起；**新增交集 → 按拆分质量问题升级：收归/串行/回 architect**）——防"矩阵提取不完整"的假阴性；
5. 冲突处理：文件面不相交假设下冲突应趋零；出现冲突 = 拆分质量问题信号 → 回 architect 复盘文件面矩阵，禁止现场硬解。

## 5. CR 变更请求通道（变更点上报）

worker 在**将要偏离冻结契约或修改非自己文件面的文件时**，不直接改，向上报 CR：

```
CR-{planId}-{seq}: {发起者 | 涉及契约/文件 | 变更内容 | 影响面声明 | 紧急度}
```

（seq 含 worker 短标识或时间戳防并发撞号。）

**交互模型**: 默认**"完成时携带 CR"**（worker 停止受影响部分的修改、其余继续、随完成返回上报——保守可执行）；预检④证实平台支持中途交互时可升级实时。批准/驳回后由主 Agent **重派 worker 重入同 worktree**（"广播"=下次任务书注入契约差分）。

| 仲裁结果 | 主 Agent 动作 |
|---------|--------------|
| **批准** | 更新契约基线 → 定向广播给受影响 worker → worker 继续 |
| **驳回** | worker **就地回退至原契约/文件面并留痕**（禁止已发生的偏离写入代码），按原契约实现 |

CR 产生在**变更点**（非终态）；CR 记录落盘检查点正文（不新增目录）。🚨 禁止 worker 间 P2P 互推沟通（破坏审计独立性面与账本可追溯性——契约变更是主 Agent 单通道仲裁职责）。

## 6. worktree 使用协议

| 约束 | 说明 |
|------|------|
| **仅平台托管** | 使用 `isolation: worktree`（平台自动创建/清理）；🚨 禁止手动 `git worktree add`（防闲置考古现场——存量教训：闲置 worktree 落后主分支 2 月） |
| **卫生** | worktrees 目录在 .gitignore 内；闲置清理走人工裁决（§编排 G 阶段） |

**适用矩阵**：

| 场景 | 适用度 | 原因 |
|------|-------|------|
| 独立页面/模块开发 | ✅ 高 | 文件面清晰 |
| 多端并行（前端/后端/AI） | ✅ 高 | 端级目录天然分区 |
| 探索性 spike/方案对比 | ✅ 最高 | 失败即弃，平台自动回收 |
| 跨模块契约变更 | ⚠️ 低 | 契约热点——单一 owner 或走 CR |
| 共享基础设施改造 | ❌ 不适用 | 公共依赖——先行串行 |
| 表结构/数据迁移 | ⚠️ 中 | SQL 脚本交叉可能——单 owner |

## 7. 路径与命令纪律

1. **路径基准（三方统一）**: 授权面/申报/变更清单统一使用**主仓根相对路径（逻辑路径）**；worker **写域 = 自身 worktree 根（首动作 pwd 回传）拼接逻辑路径**；🚨 **主工作区（含绝对路径）只读**——禁止任何主区写入与 refs 手术；
2. 🚨 worker 命令/读写使用绝对路径且必须落在**自身 worktree 写域内**（bash cwd 调用间重置——相对路径必失效）；
3. 构建验证双层：worker 内跑**本域**构建命令（新 worktree 首次构建前安装本域依赖——**环境性失败不计入修复计数**）；主 Agent 汇聚后跑**全量**构建 + 场景级验证 + Playwright；
4. worker 禁跑跨域构建（浪费 + 路径污染）。

## 8. 嵌套约束

worker 显式声明 `disallowedTools: [Agent]`（平台文档字段）——IDE 侧天然无 Agent 工具（实测），CLI 侧由此显式禁用；审计者复用 code-reviewer（只读三工具，天然无 Agent）。**全链路禁嵌套，审计一律主 Agent 顶层编排。**

## 9. 降级路径（显式声明不阻断）

| 降级触发 | 降级动作 |
|---------|---------|
| worktree 物理隔离不可用（预检①失败） | **fail-closed**: 不进入 --parallel——回常规 god 逐 plan 串行（无隔离不并行；登记原因） |
| 只读审计体无写盘能力（code-reviewer 类无写工具） | 报告由主 Agent 持久化（现状机制）；**worker 代码写盘**若平台实证不支持 → 并行方案整体不可用（fail-closed——预检验证） |
| 子 plan = 1 | 不进入并行模式（回常规 god） |
| 子 plan > 平台并发上限 | 执行分批（分批登记） |
