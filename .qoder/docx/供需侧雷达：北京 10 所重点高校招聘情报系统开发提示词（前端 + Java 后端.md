供需侧雷达：北京 10 所重点高校招聘情报系统开发提示词（前端 + Java 后端）
用途： 将本文整体交给 Cursor、Claude Code 或其他 AI
编程工具作为开发任务说明。
范围： 供需侧雷达前端 + Java 后端 + 高校公开网站采集 + 数据库 +
REST API。
首批范围： 仅采集本文列出的北京 10 所高校，不得擅自扩展。
核心边界：
供给侧追踪重点企业在高校举办的宣讲会；需求侧追踪高校双选会/招聘会的企业报名时间、举办时间和地点。双选会不检索、采集或统计参会企业名单。

你是一名资深 Java
后端工程师、前端工程师、网页采集工程师和招聘竞争情报产品架构师。

请在现有「阳光校招情报与人才战略决策系统」中开发供需侧雷达模块。开始前先检查当前工程结构、前端框架、后端框架、数据库、路由、顶部导航、认证权限和公共组件，优先复用现有实现。不得重建整个系统或修改无关模块。

本次需要完成前端和后端： -
前端页面、筛选、统计、列表、详情、日历和布局分析。 - Java
采集框架、站点适配器、字段标准化、去重、数据库、API 和任务调度。 - 不做
Excel 导出。 - 不使用 Python。 - 不把 Mock 数据冒充真实采集结果。 -
不声称未验证的网站已经采集成功。

- 发布高校、高校城市。

- 活动状态、核验状态。

- 发布高校、高校城市。
- 活动名称、原始栏目名称、活动类型。
- 校内/校外/线上/混合/未知。
- 企业报名开始时间。
- 企业报名截止时间。
- 招聘会实际举办日期、开始时间和结束时间。
- 校区、场馆、详细地址。
- 报名入口、报名方式、企业报名条件。

4.3 双选会禁止项
双选会不需要检索、采集、展示或统计参会企业名单。
不得采集参会企业列表、企业数量、企业排名、企业展位或企业参会状态。需求侧只回答：哪所高校举办、企业何时报名、何时截止、活动何时举行、在哪里举办、如何报名。
4.4 报名状态
建议状态： - NOT_OPEN：尚未开放报名。 - OPEN：开放报名。 -
CLOSING_SOON：即将截止。 - CLOSED：报名已截止。 -
NOT_PUBLISHED：暂未公布。 - CANCELLED：活动取消。 -
NEEDS_REVIEW：待核验。

"即将截止"的时间阈值应配置化，例如未来 72
小时。截止时间未知时不得显示开放或即将截止。活动状态与核验状态分开存储。

六、Java 后端与采集架构
6.1 技术栈
优先复用现有工程。没有既有约束时建议： - Java 17。 - Spring Boot。 -
Jsoup 解析普通 HTML。 - Java HttpClient 或 OkHttp 发起请求。 -
Playwright for Java 处理确实需要 JavaScript 的公开页面。 - Jackson 解析
JSON。 - MyBatis-Plus 或现有 ORM。 - MySQL 或现有数据库。 - Spring
Scheduler 或 Quartz 调度。 - SLF4J + Logback 记录日志。

不使用 Python。不要假设所有学校使用相同页面结构。优先解析公开 HTML
或允许访问的公开接口，只有确实需要时才使用浏览器自动化。
6.2 采集架构
采用： 高校配置 + 站点发现器 + 通用解析器 + 高校专用适配器 +
活动分类器 + 标准化 + 去重更新 + 数据库 + REST API。

适配器接口建议： - discoverSources()：发现就业活动入口。 -
fetchList()：获取列表。 - parseList()：提取活动候选。 -
parseDetail()：提取详情。 - normalize()：标准化字段。 -
classify()：判断活动类型、地点和核验状态。

栏目关键词作为候选发现线索，包括宣讲会、校园宣讲、双选会、招聘会、就业活动、招聘活动、就业市场、招聘信息、通知公告、招聘日历、企业进校等。关键词不能直接决定最终分类；必须结合详情页标题、正文、原始类型、地点和安排判断。
6.3 任务调度
支持： - 单校采集。 - 10 所高校全部采集。 - 仅采集重点企业宣讲。 -
仅采集双选会报名机会。 - 指定时间范围的增量采集。 - 失败任务重试。

记录任务开始/结束时间、处理数、成功数、失败数和错误摘要。单校失败不能中断全部高校任务。
6.4 合规与稳定性
只采集符合网站规则的公开信息；检查
robots.txt、使用条款和访问限制。设置合理请求频率、超时、有限重试和退避。遇到登录、验证码、403、429
或明确访问限制时停止盲目重试，记录原因，不得绕过访问控制。一次请求失败不能删除已有数据。所有活动保留来源
URL 和采集时间。

八、REST API

- GET /api/supply-demand-radar/schools：高校列表和采集状态。

- GET /api/supply-demand-radar/company-talks：重点企业宣讲列表，支持企业类别、企业、高校、城市、日期、状态、关键词、分页和排序。

- GET /api/supply-demand-radar/job-fairs：双选会列表，支持高校、城市、地点属性、报名状态、截止日期、举办日期、是否有报名入口、分页和排序。

九、数据质量与核验
原始数据和标准化数据分离，保留原始标题、原始时间文本、栏目名称和来源
URL。

核验状态： - VERIFIED：关键字段已核验。 -
NEEDS_REVIEW：存在不确定字段。 - FAILED：采集失败或详情无法读取。

活动状态与核验状态必须分开。例如活动可以是"未开始 + 待核验"。

时间处理要求： - 使用 Java java.time。 - 时区统一 Asia/Shanghai。 -
只有上下文可靠时才补全年份。 - 报名截止时间缺失时保持为空。 -
地点缺失时保持为空。 - 结束时间缺失时不自行补齐。 -
活动延期或取消时更新状态并保留历史。 -
"即将截止"依据明确截止时间和当前时间计算。

后台任务状态至少展示：候选记录数、成功解析数、新增数、更新数、重复数、待核验数、失败高校数及失败原因。候选记录数不能直接当作已确认活动数。
