# §一 项目背景与目标

## 1.1 系统定位

在现有「阳光校招情报与人才战略决策系统」中新增 **「供给端雷达」** 页签模块：自动采集各高校就业信息网公开发布的宣讲会 / 双选会 / 招聘会 / 就业活动，结构化入库，并通过 Web 页面按高校、分类、时间多维筛选展示，替代人工逐站浏览记录。

```
┌────────────────────────────────────────────────────────────────┐
│  供给端雷达 Web 页面（Vue 2.6.12 + iView 4.0.1）                 │
│  统计卡片 → 筛选区 → 分类页签 → 活动列表 → 详情抽屉 → 高校分组   │
└───────────────────────────┬────────────────────────────────────┘
                            │ 7 个 REST 端点（统一响应壳）
┌───────────────────────────▼────────────────────────────────────┐
│  java_bff（Spring Boot 3.5.3 / Java 17 / MyBatis-Plus）         │
│  ├─ 查询服务：活动列表 / 统计 / 详情 / 高校列表 / 采集状态        │
│  └─ 采集服务：站点适配器 → 栏目发现 → 详情解析 → 分类 → 去重入库  │
└──────────┬──────────────────────────────────┬──────────────────┘
           │ JDBC                             │ HTTP（Jsoup / Playwright）
┌──────────▼──────────┐              ┌────────▼──────────────────┐
│ MySQL `sunshine`    │              │ 54 所高校就业信息网         │
│ 4 张业务表           │              │ （公开页面·只读采集对象）    │
└─────────────────────┘              └───────────────────────────┘
```

# §三 全局机制需求

> 全部页面的公共基础。以下四项不得缺：认证 / 权限 / 响应壳 / 枚举常量。

## 3.1 认证与 Token（沿用现有）

| 编号 | 规则 |
|------|------|
| A1 | Token 来源：现有系统登录后写入 `localStorage`（`token` / `userToken`） |
| A2 | 请求注入：现有 axios 拦截器自动加 `token` / `userToken` 请求头（**复用，不重复实现**） |
| A3 | 失效处理：响应 `status==401/403` → 前端跳 `sessionFail`；`resultCode==='2'` → `unAuth`（现有拦截器已实现） |
| A4 | 供给端雷达接口**不新增鉴权机制**，沿用全局拦截器 |

## 3.2 权限体系

| 编号 | 规则 |
|------|------|
| P1 | 单一角色，所有登录用户权限一致 |
| P2 | 不做数据归属二次校验（全员可见全部采集数据） |
| P3 | 后端仍须校验登录态（未登录返回 401） |

## 3.3 统一请求层与响应约定（强制——唯一响应壳）

> 🚨 **全包仅此一套响应壳**，沿用现有系统 `{status, message, result}`，**不是** PRD 建议的 `{code, message, data}`。

### 3.3.1 响应壳结构

```json
{ "status": "success", "message": "", "result": { } }
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `status` | string \| number | `success` = 业务成功；`fail` = 业务失败；`401`/`403`/`304`（数字或字符串） = 会话/权限跳转（现有拦截器口径） |
| `message` | string | 失败时为可读说明；成功可为空串 |
| `result` | object/array/null | 业务数据；失败为 `null` |

> 现有前端拦截器另有遗留判断 `resultCode==='2'`（跳 unAuth）；**本模块响应不输出该字段**，不影响现有逻辑。

### 3.3.2 错误口径

| 场景 | HTTP | status | 前端行为 |
|------|------|--------|---------|
| 成功 | 200 | `success` | 正常渲染 |
| 参数非法 | 200 | `fail` | `message` 提示 |
| 未登录 | 200 或 401 | `401` | 跳 `sessionFail` |
| 无权限 | 200 或 403 | `403` | 跳 `sessionFail` |
| 服务异常 | 500 | `fail` | 提示"请求失败"并 Sentry 上报 |

### 3.3.3 分页结构（强制——单套）

```json
{
  "status": "success",
  "message": "",
  "result": {
    "list": [ ],
    "total": 0,
    "page": 1,
    "size": 20,
    "totalPages": 0
  }
}
```

> 分页**必须后端处理**；`size` 默认 20，可选 10/20/50/100。

### 3.3.4 写操作返回值

- 启动采集 `POST /crawl-tasks` → `result` = `{ "taskId": 123, "status": "PENDING" }`。
- 核验状态为只读展示，**本版不提供核验写入操作**。

### 3.3.5 字段映射声明（强制）

> DB `snake_case` → API `camelCase` 默认由 MyBatis-Plus 驼峰映射处理；**非同名字段必须显式 DTO 映射**：`university_site.id → schoolId`、`crawl_status → lastCrawlStatus`；`employment_event.school_id → schoolId` 等。禁止依赖隐式映射导致字段缺失或错位。

## 3.4 页面布局框架

| 编号 | 规则 |
|------|------|
| L1 | 页面挂载于现有主框架（顶部导航 + 内容区），沿用现有 `Menu.vue` 顶部页签 |
| L2 | 「供给端雷达」作为独立页签接入；**若导航中已存在则不重复添加** |
| L3 | 初始化顺序：读取筛选默认值 → 请求统计 + 高校列表 + 活动列表（可并行）→ 渲染 |
| L4 | 视觉规范：主色 `#F58220`、背景暖白/浅灰、卡片白、重要数据橙色、文字深灰 |

## 3.5 安全

| 编号 | 规则 |
|------|------|
| S1 | 外部采集内容入库前做 HTML 转义/白名单清洗，前端渲染用文本绑定（禁 `v-html` 直出未清洗内容） |
| S2 | 原始来源链接 `target=_blank` 打开，加 `rel="noopener noreferrer"` |
| S3 | 数据库凭据不入代码/文档/日志 |

## 3.6 消息与交互规范

| 编号 | 规则 |
|------|------|
| M1 | 成功提示：iView `$Message.success`，1.5s 自动消失 |
| M2 | 危险操作（触发全量采集）需二次确认 `$Modal.confirm` |
| M3 | 行级/按钮 loading：采集任务运行期间「立即更新」按钮禁用并显示 loading |

## 3.7 类型与常量约定（枚举全表——强制）

### 3.7.1 活动类型 `eventType`

| 值 | 含义 |
|----|------|
| `TALK` | 宣讲会 |
| `JOB_FAIR` | 双选会或招聘会 |
| `RECRUITMENT_EVENT` | 其他招聘活动 |
| `EMPLOYMENT_SERVICE` | 就业服务活动 |
| `OTHER_EMPLOYMENT_ACTIVITY` | 其他就业相关活动 |
| `UNKNOWN` | 待判断 |

### 3.7.2 地点属性 `venueType`

| 值 | 含义 |
|----|------|
| `ON_CAMPUS` | 校内 |
| `OFF_CAMPUS` | 校外 |
| `ONLINE` | 线上 |
| `HYBRID` | 线上线下混合 |
| `UNKNOWN` | 未知 |

### 3.7.3 标准分类 `standardCategory`

| 值 | 含义 |
|----|------|
| `ON_CAMPUS_TALK` | 校内宣讲会 |
| `OFF_CAMPUS_TALK` | 校外宣讲会 |
| `ON_CAMPUS_FAIR` | 校内双选会 |
| `OFF_CAMPUS_FAIR` | 校外双选会 |
| `OTHER` | 其他就业活动 |
| `PENDING_REVIEW` | 待人工核验 |

### 3.7.4 活动状态 `eventStatus`

| 值 | 含义 |
|----|------|
| `UPCOMING` | 未开始 |
| `ONGOING` | 进行中 |
| `FINISHED` | 已结束 |
| `CANCELLED` | 已取消 |
| `POSTPONED` | 已延期 |
| `UNKNOWN` | 未知 |

### 3.7.5 核验状态 `verificationStatus`

| 值 | 含义 |
|----|------|
| `PENDING` | 待核验 |
| `VERIFIED` | 已核验 |
| `REJECTED` | 已驳回 |
| `NEED_REVIEW` | 需人工复核 |

### 3.7.6 采集任务状态 `crawlTaskStatus`

| 值 | 含义 |
|----|------|
| `PENDING` | 排队中 |
| `RUNNING` | 运行中 |
| `SUCCESS` | 全部成功 |
| `PARTIAL` | 部分成功 |
| `FAILED` | 全部失败 |

### 3.7.7 高校采集状态 `schoolCrawlStatus`

| 值 | 含义 |
|----|------|
| `NEVER` | 从未采集 |
| `SUCCESS` | 成功 |
| `PARTIAL` | 部分成功 |
| `FAILED` | 失败 |

### 3.7.8 适配器类型 `adapterType`

| 值 | 含义 |
|----|------|
| `GENERIC` | 通用解析器（默认） |
| `SPECIFIC` | 需专用适配器（按学校代码登记具体适配器，如 `ZZU` / `CAUC` / `TYUT`） |

> 统一时间格式化口径：展示统一 `yyyy-MM-dd HH:mm`；日期 `yyyy-MM-dd`；后端返回 ISO 或 `yyyy-MM-dd HH:mm:ss`，前端统一格式化。

### 3.7.9 标准分类推导规则（分类器口径——强制）

| 条件 | 结果 |
|------|------|
| `eventType=TALK` 且 `venueType=ON_CAMPUS` | `ON_CAMPUS_TALK` |
| `eventType=TALK` 且 `venueType=OFF_CAMPUS` | `OFF_CAMPUS_TALK` |
| `eventType=JOB_FAIR` 且 `venueType=ON_CAMPUS` | `ON_CAMPUS_FAIR` |
| `eventType=JOB_FAIR` 且 `venueType=OFF_CAMPUS` | `OFF_CAMPUS_FAIR` |
| `eventType IN (TALK, JOB_FAIR)` 且 `venueType=ONLINE` | 保留 eventType，`standardCategory=OTHER`（线上活动归入其他，不臆断校内/校外） |
| `eventType IN (TALK, JOB_FAIR)` 且 `venueType=HYBRID` | 保留 eventType，`standardCategory=PENDING_REVIEW`，`verificationStatus=NEED_REVIEW`（需人工确认主导形式） |
| 上述任一但 `venueType=UNKNOWN` | 保留 eventType，`standardCategory` 置 `PENDING_REVIEW`，`verificationStatus=NEED_REVIEW` |
| `eventType` 为其他类型 | `OTHER` |
| 无法判断 eventType | `UNKNOWN` + `PENDING_REVIEW` |

> 🚨 不得依据高校所在地推断活动一定在校内举行。
> 🚨 6 种 `venueType` 全覆盖：ON_CAMPUS / OFF_CAMPUS / ONLINE / HYBRID / UNKNOWN 均有明确去向，无未定义组合。

# §四 功能需求（页面 #1 · 供给端雷达）

## 4.1 供给端雷达主页面

### 4.1.1 定位

单页面中枢：一屏内完成「看大盘 → 筛条件 → 切分类 → 读列表 → 看详情 → 按校分组」的完整闭环，并提供采集触发与任务观测入口。
**路由**: `/pages/supply-radar/index`（最终以菜单注册为准，留白 L6）。

### 4.1.2 布局结构

```
[第1层] 页头：标题「供给端雷达」 + 副标题 + 右上角状态区（最近采集时间/监测高校数/采集状态/立即更新/采集任务）
[第2层] 统计卡片区：监测高校数 | 活动总数 | 近期宣讲会 | 近期双选会 | 待核验数
[第3层] 筛选区：高校（搜索+多选+城市+全部） | 活动分类 | 时间（不限/今日/7天/30天/自定义） | 其他（状态/形式/核验）| 重置
[第4层] 分类页签：全部 | 校内宣讲会 | 校外宣讲会 | 校内双选会 | 校外双选会 | 其他活动（各带数量）
[第5层] 视图切换：活动列表视图 ⇄ 高校分组视图
[第6层] 内容区：
        · 列表视图：活动卡片列表 + 分页 + 排序
        · 分组视图：高校分组卡片（可展开活动列表）
[第7层] 抽屉：活动详情抽屉（右侧滑出） / 采集任务面板抽屉（右侧滑出）
```

### 4.1.3 功能区规格（字段级）

#### (a) 页头状态区

| 元素 | 控件 | 数据源 | 行为 |
|------|------|--------|------|
| 最近采集时间 | 文本 | `crawl-status` 汇总 或 `statistics` 返回 `lastCrawlAt` | 无则显示「暂无采集记录」 |

### 4.1.4 状态机

**页面前端 stage**：

```
INIT ──► LOADING ──► SUCCESS ──► (筛选/翻页) ──► LOADING
                 └──► EMPTY        （无符合条件数据）
                 └──► ERROR        （网络/接口失败，可重试）
```

| stage | 触发 | 表现 |
|-------|------|------|
| `INIT` | 首次进入 | 骨架/loading |
| `LOADING` | 请求中 | 卡片/列表 loading |
| `SUCCESS` | 有数据 | 正常渲染 |
| `EMPTY` | 结果为空 | 空态文案（4.1.9） |
| `ERROR` | 请求失败 | 错误提示 + 重试按钮 |

**采集任务状态（后端）**：`PENDING → RUNNING → SUCCESS | PARTIAL | FAILED`（终态三选一）。

### 4.1.5 关键交互流程

**流程 1：首次加载**
1. 读取默认筛选（全部高校 / 全部活动 / 未来 30 天 / eventDate asc）。
2. 并行请求：`GET /schools`、`GET /statistics`、`GET /events`。
3. 渲染统计卡片、筛选选项、分类页签数量、活动列表。
4. 空数据 → 展示空态，不伪造。

**流程 2：筛选/翻页**
1. 用户修改筛选或翻页 → 收集参数。
2. 并行请求 `GET /statistics` + `GET /events`（携带同一筛选条件）。
3. 刷新卡片、列表、分页、页签数量。
4. 重置按钮 → 回默认并重新请求。

**流程 3：查看详情**
1. 点击卡片「查看详情」→ `GET /events/{id}`。
2. 右侧抽屉滑出，展示 11 项（4.1.6）。
3. 缺失字段统一显示「暂无公开信息」。
4. 「打开原始来源」→ `window.open(sourceUrl)` 新标签页。

**流程 4：立即更新**
1. 点击「立即更新」→ 二次确认 `$Modal.confirm`。
2. `POST /crawl-tasks {taskType:"ALL"}` → 返回 `taskId`。
3. 按钮进入 loading 禁用；轮询 `GET /crawl-tasks/{taskId}`（3s/次，最多 100 次）。
4. 终态（SUCCESS/PARTIAL/FAILED）→ 停止轮询 → 提示结果 → 刷新统计/列表/页头状态。
5. **未到终态前不得显示"成功"**。

**流程 5：采集任务面板**
1. 点击「采集任务」→ 抽屉打开。
2. `GET /crawl-status` 展示各高校最近采集状态表（校名/城市/最近时间/状态/失败原因）。
3. 支持按状态筛选、刷新。

**流程 6：视图切换**
1. 列表视图 ⇄ 分组视图切换。
2. 分组视图基于当前筛选条件重新聚合（后端提供或按筛选结果分组，口径见附录A L3 Q5）。

### 4.1.6 活动详情抽屉内容（11 项）

1. 活动基本信息（标题/来源高校/城市）
2. 活动类型与地点分类（eventType / venueType / standardCategory）
3. 日期和时间（eventDate / startTime / endTime）
4. 举办地点（venueName / eventAddress）
5. 主办单位及相关企业（organizer / companyNames）
6. 报名截止与报名方式（registrationDeadline / registrationUrl）

9. 最近采集时间（crawledAt / lastSeenAt）
10. 数据核验状态（verificationStatus）
11. 最近一次内容变更记录（来自 `employment_event_history`）

# §六 服务与集成需求

## 6.1 服务能力划分

| 能力域 | 覆盖能力 |
|--------|---------|
| 查询服务 | 高校列表 / 活动列表（分页） / 统计指标 / 活动详情 / 采集状态 |
| 采集服务 | 站点适配器 / 栏目发现 / 详情解析 / 分类 / 去重更新 / 任务调度与执行 |

## 6.2 API 端点契约（7 个——数量 = README 速览）

> 统一响应壳 §3.3。以下 `result` 为壳内数据。

### 6.2.1 `GET /api/supply-radar/schools` —— 高校列表

- **入参**: `city`（可选）、`keyword`（可选）、`enabled`（可选 0/1）
- **result**: 数组，元素 `{ schoolId, schoolCode, schoolName, schoolCity, province, siteUrl, adapterType, enabled, lastCrawlAt, lastCrawlStatus, lastFailReason }`
- **一致性**: 强一致（直接查库）
- **安全**: 参数化；仅登录用户

### 6.2.2 `GET /api/supply-radar/events` —— 活动列表（分页）

- **入参**: `schoolIds`（逗号分隔或多值）、`city`、`category`、`eventType`、`venueType`、`startDate`、`endDate`、`status`、`verificationStatus`、`keyword`、`page`（默认 1）、`size`（默认 20，上限 100）、`sortBy`（默认 `eventDate`）、`sortDirection`（默认 `asc`）
- **result**: 分页结构 `{ list[], total, page, size, totalPages }`
- **list 元素**: 活动卡片所需字段（见 4.1.3(e)）
- **一致性**: 强一致
- **安全**: 全部条件参数化（MyBatis-Plus Wrapper / `#{}`），**禁字符串拼接**

### 6.2.3 `GET /api/supply-radar/statistics` —— 统计指标

- **入参**: 与 `events` 相同的主要筛选条件
- **result**: `{ monitoredSchoolCount, totalEventCount, recentTalkCount, recentFairCount, pendingVerificationCount, lastCrawlAt, lastCrawlTaskStatus, categoryCounts:{ all, onCampusTalk, offCampusTalk, onCampusFair, offCampusFair, other } }`
- **枚举**: `lastCrawlTaskStatus` 取 3.7.6（任务级）；高校列表/采集状态中的 `lastCrawlStatus` 取 3.7.7（高校级）——**两者不同字段不同枚举**
- **口径**: 附录A L3 Q1~Q4 + 分类计数 Q4
- **一致性**: 强一致；**统计与列表使用同一筛选条件集**

### 6.2.4 `GET /api/supply-radar/events/{id}` —— 活动详情

- **result**: 完整活动字段 + `changes[]`（变更记录：`{ changeType, fieldName, oldValue, newValue, changedAt }`；`changeType` 取 `CREATED`/`UPDATED`/`CANCELLED`/`POSTPONED`）
- **异常**: id 不存在 → `status=fail`，`message=活动不存在`

### 6.2.5 `POST /api/supply-radar/crawl-tasks` —— 启动采集

- **入参**: `{ taskType: "ALL" | "SPECIFIED", schoolIds?: [], startDate?, endDate? }`
- **result**: `{ taskId, status: "PENDING" }`
- **语义**: **受理 ≠ 完成**；异步执行，终态以 `GET /crawl-tasks/{taskId}` 为准
- **幂等**: 同一时刻仅允许一个 RUNNING 任务；重复提交返回现有运行中任务 ID（幂等键 = 全局运行锁）

### 6.2.6 `GET /api/supply-radar/crawl-tasks/{taskId}` —— 查询任务

- **result**: `{ taskId, taskType, status, startedAt, finishedAt, totalCount, successCount, failCount, errorSummary }`
- **轮询**: 前端 3s/次，最多 100 次

### 6.2.7 `GET /api/supply-radar/crawl-status` —— 采集状态

- **入参**: `status`（可选）
- **result**: 数组，元素 `{ schoolId, schoolName, schoolCity, lastCrawlAt, lastCrawlStatus, lastFailReason }`

## 6.3 关键行为要求（编号强制）

| 编号 | 要求 |
|------|------|
| B1 | 采集按高校独立执行，单校失败**不中断**其他高校 |
| B2 | 采集任务状态机严格按 §3.7.6；`PARTIAL` = 有成功也有失败 |
| B3 | 去重更新在**事务**内完成（更新活动 + 写变更历史） |
| B4 | 采集前检查 `robots.txt`，遵守 `Crawl-delay`；遇限制停止并记录 |
| B5 | 请求间隔 ≥2s、超时 30s、失败重试 2 次（指数退避） |
| B6 | 遇登录/验证码/403 → 记录 `lastFailReason`，置该校状态 FAILED，不绕过 |
| B7 | 统计与列表共用同一筛选口径（防口径漂移） |
| B8 | 全部查询参数化，禁 SQL 注入 |
| B9 | 采集内容入库前 HTML 清洗（见 §3.5 S1） |
| B10 | 定时任务（Spring Scheduler）与手动触发共用同一采集执行器 |

## 6.5 采集架构（方案 A · 混合策略）

```
站点配置(university_site) 
   │
   ▼
栏目发现（扫描候选栏目：就业活动/招聘活动/就业信息/校园招聘/招聘会/通知公告/招聘日历…）

   │

   │

   │
   ▼
持久化（employment_event / employment_event_history / university_site 状态）
```
