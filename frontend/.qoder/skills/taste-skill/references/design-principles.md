# Design Principles — 设计原则详解

本文件详述四大设计原则（CRAP）及其延伸原则。当需要构建布局、审查视觉质量、或修复"不好看"的 UI 时加载本文件。

## 一、四大核心原则（CRAP）

### 1. Contrast 对比

对比让重要信息脱颖而出。没有对比，一切都是平等的灰——没有重点。

**对比的维度：**
- 大小对比：标题 24px vs 正文 14px
- 字重对比：bold(700) vs regular(400)
- 颜色对比：主色按钮 vs 中性背景
- 间距对比：组内紧凑(8px) vs 组间宽松(24px)

**正例：**
```
订单总览                    [新建订单]
¥ 12,480.00               ← 大字号 + 主色，视觉焦点
较昨日 +8.2%               ← 小字号 + 辅助色，次要信息
```

**反例：**
```
订单总览  ¥12,480.00  较昨日+8.2%  [新建订单]
↑ 全部 14px 同字号同字重，无层次，眼睛不知道看哪里
```

**关键规则：**
- 如果两个元素不同，就让它们**明显不同**——不要 14px 和 15px，要 14px 和 24px
- 对比要大胆，犹豫的对比比没有对比更糟

---

### 2. Repetition 重复（一致性）

重复建立信任。相同的组件在相同场景下必须视觉一致。

**重复的对象：**
- 按钮系统：主按钮、次按钮、文字按钮，每种只有一种样式
- 间距节奏：所有卡片内边距统一，所有区块间距统一
- 字体层次：h1/h2/h3/body/caption 全局统一
- 图标风格：线性 or 面性，不要混用
- 圆角语言：全局统一圆角策略

**正例：** 三个列表页的查询区域，布局、间距、按钮样式完全一致。
**反例：** 第一个页面查询按钮在右上角蓝色，第二个在左下角灰色，第三个居中绿色。

**关键规则：**
- 复用样式，而非每页重造
- 一致性 > 创意（在后台系统中尤其如此）

---

### 3. Alignment 对齐

对齐是秩序的基础。错位的元素制造视觉噪音。

**对齐策略：**
- 选择一条主对齐线（通常是左对齐），让所有元素向它靠拢
- 表单：标签和输入框共享同一垂直基线
- 表格：数字右对齐，文本左对齐，状态居中
- 卡片网格：使用统一的 gutter，不要手动调 margin

**正例：**
```
姓名：  [张三        ]
部门：  [技术部      ]
角色：  [管理员      ]
        ↑ 冒号对齐，输入框左边对齐
```

**反例：**
```
姓名：[张三]
部门：  [技术部]
角色：    [管理员]
↑ 无对齐基准线，杂乱
```

**关键规则：**
- 用 flexbox / grid 的对齐能力，不要用 margin/padding 手动"凑"对齐
- 居中要明确意图——标题居中是设计选择，数据居中通常是错误

---

### 4. Proximity 亲密性

相关元素靠近，不相关元素远离。亲密性表达"这些是一组的"。

**间距节奏：**
| 关系 | 推荐间距 |
|------|----------|
| 标签与输入框（同组内） | 4-8px |
| 表单项之间（同组内） | 16-24px |
| 不同区块之间 | 32-48px |
| 卡片之间 | 16-24px |

**正例：**
```
[个人信息]                    ← 区块标题
姓名：[  ]  手机：[  ]       ← 组内紧凑 16px

                              ← 区块间 32px 留白

[工作信息]                    ← 另一区块
职位：[  ]  部门：[  ]
```

**反例：**
```
[个人信息]
姓名：[  ]
          ← 不必要的过大间距（24px）让姓名"脱组"
手机：[  ]
```

**关键规则：**
- 留白是分组工具：间距大 = 不同组，间距小 = 同一组
- 不要给每个元素都加相同的 margin——差异化的间距才传递结构

---

## 二、视觉层次

一个视图必须有一个明确的视觉焦点。眼睛 0.5 秒内知道"先看哪里"。

### 建立层次的手段（按力度排序）

1. **大小**：最强烈的层次信号
2. **颜色/对比度**：主色 vs 中性色
3. **字重**：bold vs regular
4. **间距**：焦点元素周围更多留白
5. **位置**：左上角（阅读起点）天然权重更高

### 层次金字塔

```
        ┌─────────┐
        │ Level 1 │  页面标题 / 主数据（1个）
        ├─────────┤
       │ Level 2  │  区块标题 / 关键操作（2-5个）
      ├───────────┤
     │  Level 3   │  正文 / 表单标签 / 常规按钮
    ├─────────────┤
   │   Level 4    │  辅助说明 / 时间戳 / 次要操作
  └───────────────┘
```

**规则：** 每一级之间必须有可感知的差异。Level 1 和 Level 2 不能只差 2px。

---

## 三、留白策略

留白不是"空"，是呼吸。拥挤的界面 = 低端感。

### 留白原则

- **内部留白（padding）** < **外部留白（margin）**：内容与容器边界的距离，小于容器与容器之间的距离
- **密度适配场景**：数据密集型表格可以紧凑，但卡片/表单必须有呼吸感
- **黄金留白比例**：区块间距 ≈ 区块内边距的 1.5-2 倍

### 企业后台密度参考

| 场景 | 推荐密度 |
|------|----------|
| 数据表格 | 紧凑（行高 40-48px，内边距 8-12px） |
| 表单页 | 适中（项间距 24px，输入框高 32-36px） |
| 仪表盘卡片 | 宽松（内边距 24px，卡片间距 16-24px） |
| 详情页 | 宽松（区块间距 32-48px） |

---

## 四、平衡与节奏

### 平衡

- **对称平衡**：左右镜像，适合正式、稳定的场景（登录页、详情头部）
- **不对称平衡**：一侧大元素 + 另一侧多个小元素，视觉重量相等，更有活力
- 不要让页面"头重脚轻"或"左重右轻"

### 节奏

- 重复的间距模式产生节奏感：8 → 16 → 8 → 16
- 节奏断裂 = 视觉卡顿 = 不和谐
- 保持间距值的统一序列（全部是 4 的倍数）

## 五、反模式目录（附修复方案）

### 1. 彩虹调色盘
**症状**：页面出现 5+ 种不相关的彩色。
**修复**：1 个主色 + 语义色（成功/警告/错误/信息）+ 中性灰阶。其余一律中性色。

### 2. 按钮动物园
**症状**：同类操作按钮样式各不相同。
**修复**：建立 3 种按钮——主按钮（主色填充）、次按钮（边框/幽灵）、文字按钮（无背景）。全项目复用。

### 3. 文字墙
**症状**：大段无层次文字，无标题无间距。
**修复**：拆分段落 → 加小标题 → 关键信息加粗/变色 → 段间增加 16px 间距。

### 4. 错位表单
**症状**：标签和输入框基线不齐，长短不一。
**修复**：统一 label 宽度（如 `width: 80px; text-align: right`），输入框统一高度。

### 5. 阴影滥用
**症状**：每个元素都有重阴影，页面像"漂浮"。
**修复**：扁平为默认。仅 hover/弹层/抽屉等"浮起"元素使用阴影，且按 elevation 等级递进。

### 6. 迷你点击区
**症状**：可点击元素小于 32px，难以点中。
**修复**：交互元素最小 32px（移动端 44px），用 padding 撑大点击区而非只靠文字大小。

### 7. 无意义动效
**症状**：所有元素都有 transition，hover 时疯狂跳动。
**修复**：动效服务于反馈（hover、loading、状态切换），时长 150-300ms，缓动函数用 `ease`。

### 8. 对齐漂移
**症状**：元素间差 1-3px 的微 misalignment，肉眼可见但不明显。
**修复**：用 flex/grid 对齐替代 margin 手动定位，消除亚像素误差。

### 9. 图标混用
**症状**：同一页面混用线性图标和面性图标，或不同图标库混用。
**修复**：统一图标风格（全线性 or 全面性），统一图标库，统一尺寸（16/20/24）。

### 10. 灰底灰字
**症状**：浅灰背景上用浅灰文字，对比度不足。
**修复**：文字与背景对比度 ≥ 4.5:1（WCAG AA）。用对比度工具验证。
