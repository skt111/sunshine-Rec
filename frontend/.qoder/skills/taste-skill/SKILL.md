# Taste Skill — 审美说明书

## 概述

一份赋予 AI 审美判断力的说明书。超越让代码"能跑"，本技能确保生成的界面看起来精致、专业、视觉协调。核心原则见 `references/design-principles.md`；具体视觉系统（配色、字号、间距、阴影）见 `references/visual-system.md`。两者均按需加载，以保持上下文精简。

## 适用场景

当工作涉及视觉输出时加载本技能：

- 创建或编辑渲染 UI 的 `.vue`、`.html`、`.css`、`.scss` 文件
- 设计布局、页面、表单、表格、卡片、弹窗或任何组件
- 选择颜色、字体、间距、内边距、外边距、圆角或阴影
- 构建响应式或移动端布局
- 审查现有 UI 的视觉质量并提出改进建议
- 将设计稿转换为代码

## 核心审美红线（必须遵守）

1. **对齐不可妥协** —— 每个元素都要对齐到共享网格或另一元素。绝不允许出现边缘错位的"漂浮"元素。
2. **间距一致** —— 使用 8px 间距尺度（4 / 8 / 12 / 16 / 24 / 32 / 48）。绝不使用 `7px`、`13px`、`15px` 等随意值，除非为修正特定渲染问题。
3. **配色克制有目的** —— 一个主品牌色、语义色（成功/警告/错误/信息）加一组中性灰阶。绝不随意散落 hex 值；从 `references/visual-system.md` 的色板中取色。
4. **视觉层次清晰** —— 视线必须知道先看哪里。通过大小、字重、颜色、间距实现，而非全部同时使用。
5. **留白是特性，不是浪费** —— 区块之间要有呼吸感。拥挤的界面意味着低质量。
6. **对比度保证可读性** —— 正文与背景对比度须达 WCAG AA（4.5:1）。绝不在白底上使用浅灰文字。
7. **重复建立信任** —— 相同组件在相同场景下必须视觉一致。复用样式，而非每页重造。
8. **拒绝装饰性噪音** —— 避免无意义的渐变、阴影、边框和动画。每个视觉效果都必须服务于信息传达。

## 使用方法

### 1. 按需查阅参考文档

| 参考文档 | 涵盖内容 | 加载时机 |
|-----------|--------|-----------|
| `design-principles.md` | 四大设计原则（CRAP：对比、重复、对齐、亲密性）、层次、留白、平衡、反模式 | 开始新布局、审查视觉质量、修复"丑"界面时 |
| `visual-system.md` | 具体令牌：色板、字号尺度、间距尺度、圆角、阴影层级、图标规范 | 选择颜色、字体、间距或阴影时；构建设计令牌时 |

### 2. 主动应用原则

生成 UI 代码时，默认应用以下规则，而非询问用户：

- **间距**：相关元素间默认 `16px`，区块间 `24px` 以上。
- **字号**：遵循模数字号尺度——绝不使用随意字号。
- **配色**：从定义的色板取色。语义色仅用于其语义含义（红色=错误，而非装饰）。
- **阴影**：使用系统中的层级。默认扁平；仅对交互/hover 元素提升层级。
- **圆角**：同一上下文内保持一致（如所有卡片 `4px`，所有按钮 `2px`）。
- **对齐**：优先使用 flexbox/grid 对齐，而非手动 margin 拼凑。

### 3. 自检清单

宣布 UI 工作完成前，对照以下清单核查：

- [ ] 每个元素都对齐到网格或相邻元素
- [ ] 间距值来自尺度（无随意数字）
- [ ] 颜色来自色板（无色板外 hex 值）
- [ ] 文字与背景对比度达 4.5:1
- [ ] 视觉层次清晰——每个视图只有一个主焦点
- [ ] 留白分隔逻辑分组；无拥挤感
- [ ] 一致组件在各页面外观相同
- [ ] 无无目的的装饰性渐变/阴影/动画

### 4. 常见反模式（需避免）

快速参考——完整列表及修复方案见 `references/design-principles.md`：

- **彩虹调色盘**：使用 5+ 种不相关颜色。修复：1 主色 + 语义色 + 中性色。
- **按钮不一致**：同类操作按钮的 padding/圆角/颜色各不相同。修复：统一按钮系统。
- **文字墙**：无标题、无间距、无层次。修复：拆分区块，增加视觉权重。
- **表单错位**：标签和输入框基线略有偏差。修复：共享网格，统一高度。
- **阴影滥用**：每个元素都有重阴影。修复：仅对浮起/交互元素使用层级阴影。
- **迷你点击区**：可点击区域小于 32px。修复：交互元素最小 32px（理想 40px+）。

### 5. 与其他技能的关系

- **`frontend-code-style`**：定义*如何写* CSS/SCSS（缩进、排序、语法）。本技能定义*什么好看*。两者配合使用——style 管格式，taste 管审美。
- **`intelproduct-web-dev`**：项目级组件规范。当本项目使用 iView UI 时，优先采用 iView 内置设计令牌；本技能补充整体审美判断。
- **`CLAUDE.md`**：项目上下文在业务约束上优先。本技能治理纯视觉质量。
